# P0-2 统一远程渠道（Channels）落地方案

> 目标：把 my-cowork 目前的「仅飞书 webhook」扩展为 **统一渠道体系**（Telegram / Lark / DingTalk / 微信 / 企微 / 扩展渠道），包含「Bot Token 测试 → 启用 → 配对请求 → 批准/拒绝 → 授权用户 → 撤销」完整流程。
> **对齐基准：AionUi Channels 实现**（本方案每个功能点都标注对应 AionUi 源码文件，实现时逐条对照，保持一致）。

## 1. 目标与非目标

### 1.1 目标
- 一套通用 Channel 抽象，任意 IM 渠道按同一契约接入（内置 + 扩展）。
- 完整配对授权生命周期（与 AionUi F-WEBUI-20 一致）。
- 授权用户发消息 → 后端建任务（复用 `TaskManager.handle`）→ 任务结束 → 渠道回发结果。
- 渠道级绑定：**助手（assistant + skills）** 与 **默认模型**（对齐 AionUi F-WEBUI-18/19）。

### 1.2 非目标（本期明确不做，避免范围蔓延）
- Slack / Discord（保留 coming_soon 占位，与 AionUi 一致）。
- 多渠道会话多轮上下文完整持久化（本期做「任务级会话」，`sessions` 表仅记录映射，不做消息历史回灌）。
- 微信扫码/企微长连接适配器（本期只做接口预留，UI 仍显示 coming_soon 或 disabled）。
- 渠道插件的外部安装/市场（extension 动态安装机制），本期只支持**内置插件 + 配置文件注册**。

## 2. 架构与分层

```
渲染进程                     Electron 主进程                   Python 后端 (FastAPI)
ChannelsPanel ──IPC/HTTP──▶ tunnel.ts(cloudflared)  ◀─webhook── 渠道回调(Lark/DingTalk)
    │                            │                              │
    └──SSE /api/channel/stream◀──┴──TraceBus/ChannelBus──────────┤
                                                                 ▼
                        app/server/channels/  (L9 入口层·新包)
                          ├─ ChannelManager  (注册表/启停/配对/测试)
                          ├─ plugins/        (telegram/lark/dingtalk/扩展 适配器)
                          ├─ store.py        (~/.my-cowork/channels.db)
                          └─ settings.py     (渠道→助手/模型绑定)
                                │ 调用
                                ▼
              app.orchestrator.task_manager.TaskManager (L8, submit/handle)
                                │
              app.guardrails.policy.skill_usable_via_remote (L4 远程安全策略)
```

**分层合规说明**：`app.server.channels` 属于 L9 入口层，`app.server` 已在 `.importlinter` layers 契约中，可向下依赖 orchestrator/tools/guardrails，**无需改契约**；渠道插件不跨层 import 业务层内部细节，只通过 ChannelManager 门面调用。

### 2.1 关键设计决策（对齐 AionUi）
1. **插件契约即扩展契约**：AionUi 用 `aion-extension.json` 的 `contributes.channelPlugins` 描述插件（type/name/icon/entryPoint/credentialFields/configFields），适配器实现 `start/stop/isRunning/getBotInfo/sendMessage/editMessage/ingestIncomingEvent`。my-cowork 以**同构 Python 类**实现同一契约（`ChannelPlugin` ABC），内置渠道 = 注册好的内置插件。
2. **凭据与配置分离**：`credentialFields`（Token/AppSecret，落 keychain/加密存储）+ `configFields`（如 enableMetrics，落 channels.db）；与 AionUi「tokenLocked：授权后禁改，须先禁用并清空授权用户」一致。
3. **配对授权**：非授权用户发消息 → 生成 10 分钟有效 pairing（code=UUID）→ 推 `channel.pairing-requested` → 用户在客户端批准/拒绝 → 批准后建 `authorized_user` + 会话 → 推 `channel.user-authorized`。
4. **任务回执**：授权用户消息 → `TaskRequest(text, source="channel.<type>", reply_chat_id=<chat_id>, assistant_id=<绑定助手>, enabled_skill_ids=<绑定skills>)` → `TaskManager.handle` 异步执行 → `graph.end` 事件 → 渠道 `send_message(chat_id, 结果摘要)`。含确认类工具的 Skill 仍走 `skill_usable_via_remote` 拒绝（复用现有策略）。
5. **SSE 替代 WS**：`ChannelBus`（内部事件总线，订阅 TraceBus 或独立）→ `GET /api/channel/stream`（EventSource，长期连接）。事件名沿用 AionUi：`channel.pairing-requested` / `channel.plugin-status-changed` / `channel.user-authorized`。

## 3. 数据模型（对齐 AionUi `channel.ts`）

SQLite 单库 `~/.my-cowork/channels.db`，表：

```sql
-- 插件状态/凭据（凭据仅存 keychain 引用，不落明文）
CREATE TABLE channel_plugins (
  plugin_id   TEXT PRIMARY KEY,        -- 'telegram' | 'lark' | ...
  type        TEXT NOT NULL,
  name        TEXT NOT NULL,
  enabled     INTEGER NOT NULL DEFAULT 0,
  connected   INTEGER NOT NULL DEFAULT 0,
  has_token   INTEGER NOT NULL DEFAULT 0,
  status      TEXT,                     -- 'active' | 'inactive' | 'error'
  last_connected INTEGER,               -- epoch ms
  credential_ref TEXT,                  -- keychain account 引用
  config      TEXT,                     -- JSON configFields
  extension_meta TEXT,                  -- JSON（扩展渠道用）
  updated_at  INTEGER
);

-- 配对请求（AionUi IChannelPairingRequest）
CREATE TABLE channel_pairings (
  code            TEXT PRIMARY KEY,
  platform_user_id TEXT NOT NULL,
  platform_type   TEXT NOT NULL,
  display_name    TEXT,
  requested_at    INTEGER NOT NULL,
  expires_at      INTEGER NOT NULL
);

-- 授权用户（AionUi IChannelUser）
CREATE TABLE channel_users (
  id              TEXT PRIMARY KEY,
  platform_user_id TEXT NOT NULL,
  platform_type   TEXT NOT NULL,
  display_name    TEXT,
  authorized_at   INTEGER NOT NULL,
  last_active     INTEGER,
  session_id      TEXT,                 -- 最近会话映射
  UNIQUE(platform_type, platform_user_id)
);

-- 渠道会话映射（AionUi IChannelSession）
CREATE TABLE channel_sessions (
  id            TEXT PRIMARY KEY,
  user_id       TEXT NOT NULL,
  platform_type TEXT NOT NULL,
  chat_id       TEXT,                   -- IM chat id
  conversation_id TEXT,                 -- my-cowork session id
  task_id       TEXT,
  created_at    INTEGER NOT NULL,
  last_activity INTEGER NOT NULL
);

-- 渠道平台设置（AionUi IChannelPlatformSettings）
CREATE TABLE channel_settings (
  platform      TEXT PRIMARY KEY,
  assistant_id  TEXT,                   -- 绑定助手
  enabled_skill_ids TEXT,               -- JSON array
  default_model_id TEXT,                -- 默认模型 profile id（预留）
  default_model_use TEXT
);
```

## 5. 渠道插件契约（对齐 AionUi `ext-feishu-channel.js`）

```python
# backend/app/server/channels/base.py
class ChannelPlugin(ABC):
    def __init__(self, config: dict): ...
    @abstractmethod
    async def start(self) -> dict: ...            # {ok: True, plugin: id}
    @abstractmethod
    async def stop(self) -> dict: ...             # {ok: True}
    @abstractmethod
    def is_running(self) -> bool: ...
    @abstractmethod
    def get_active_user_count(self) -> int: ...
    @abstractmethod
    def get_bot_info(self) -> dict: ...           # {display_name, ...}
    @abstractmethod
    async def send_message(self, chat_id: str, message: str) -> str: ...   # -> msg_id
    async def edit_message(self, chat_id, message_id, message): ...        # 可选
    async def ingest_incoming_event(self, event: dict) -> dict:            # {ok, deduped}
```

- **事件去重**：对齐示例 `EVENT_TTL_MS = 5 * 60 * 1000`，`processedEvents` map 去重。
- **插件描述**：`ChannelPluginMeta`（dataclass）：`id/name/description/icon/credential_fields/config_fields/entry_point`，对应 `aion-extension.json` 的 `contributes.channelPlugins`。
- **内置插件**（本期）：
  - `telegram`：轮询 `getUpdates`（**不需要 tunnel**），`credentialFields=[bot_token]`。
  - `lark`：webhook 回调（复用现有 `webhook_lark` 验签 + `tunnel.ts`），`credentialFields=[app_id, app_secret]`（AionUi Lark 用 appId/appSecret）。
  - `dingtalk`/`weixin`/`wecom`：本期仅注册 meta（UI 显示 disabled/coming_soon），接口预留。

## 6. 事件流（配对 & 任务回执）

### 6.1 配对授权（对齐 AionUi F-WEBUI-20）
```
用户 DM Bot ──▶ 适配器 ingest_incoming_event（去重）
   ├─ 已授权用户 ──▶ 提交任务（见 6.2）
   └─ 未授权用户 ──▶ ChannelManager.create_pairing(code=uuid, 10min)
                       ──▶ emit channel.pairing-requested ──▶ SSE ──▶ 客户端弹配对卡片
客户端 Approve ──▶ POST /api/channel/pairings/approve {code}
   ──▶ ChannelManager.approve → 建 channel_users + 初始化 session
       ──▶ emit channel.user-authorized ──▶ SSE ──▶ 客户端刷新授权用户列表
客户端 Reject  ──▶ POST /api/channel/pairings/reject {code}（删除 pairing，可选回发提示）
```

### 6.2 授权消息 → 任务 → 回执
```
授权用户发消息 ──▶ adapter.ingest_incoming_event → ChannelManager.handle_message
   ──▶ 查 channel_settings 取 assistant_id/enabled_skill_ids（默认无绑定 → 用全局默认）
   ──▶ 查 skill_usable_via_remote：含本地确认工具的 Skill → 直接回发拒绝文案
   ──▶ TaskManager.handle(TaskRequest(text, source="channel.<type>",
                                      reply_chat_id, assistant_id, enabled_skill_ids))
   ──▶ 订阅 bus：graph.end 时 adapter.send_message(reply_chat_id, 结果摘要/产物路径)
   ──▶ 更新 channel_sessions.last_activity
```

## 9. 安全（对齐 AionUi + my-cowork 既有策略）

1. **凭据**：bot token / appSecret 经 Electron keychain（`keychain.ts`，account `channel:<plugin_id>`）存储；后端只存 `credential_ref`。
2. **授权边界**：只有 `channel_users` 里的用户消息才会触发任务；配对码 10 分钟过期。
3. **远程安全策略**：任务提交前复用 `guardrails.policy.skill_usable_via_remote`，含 fs/exec/docgen 确认类工具的 Skill 拒绝远程执行（沿用现有 `REMOTE_DENIED_MSG`）。
4. **Webhook 渠道**（lark/dingtalk）：验签 + IP 白名单 + 仅暴露 `/webhook/*`（复用 `LocalhostOnlyMiddleware` 与 `tunnel.ts`）。
5. **SSE 流**：仅本机 127.0.0.1 可读（受 `LocalhostOnlyMiddleware` 保护），不暴露公网。
6. **限流**：`channel_users` 消息按用户做频率限制（如 10 条/分钟），防刷。

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| Telegram 轮询与后端生命周期耦合（后端是子进程，重启丢失轮询态） | 轮询任务注册为 FastAPI lifespan 任务；`getUpdates` 用 offset 续传，重启不丢消息 |
| keychain 在无 GUI 环境不可用 | 复用 `keychain.ts` FileBackend 降级（现有能力） |
| 多任务并发回执错乱 | `channel_sessions` 以 chat_id 映射，回执绑定 task_id；`send_message` 失败重试 1 次 |
| SSE 断线丢失配对事件 | 客户端重连后 `GET /api/channel/pairings` 全量拉取兜底 |
| 与现有「飞书远程」Tab 重叠 | Phase 2 将旧 `tunnel` Tab 收敛为「远程连接」区，飞书渠道并入 channels 体系（webhook_lark 保留兼容路由） |
