# 任务预算

任务预算限制一次任务的累计 token 用量，独立于模型上下文窗口和单次输出长度。同一段历史在多次模型请求中重复发送，也会重复计入任务用量。

## 设置

- 在「设置 → 通用 → 任务预算」设置全局默认值。首次默认 200,000 token，可输入正整数或选择「无上限」。
- 在对话输入框下方点击「任务预算」，可为当前会话设置覆盖值，或选择「跟随全局」。
- 默认值和会话覆盖只影响新任务；每个新任务重新计数，不按整个会话累计。任务启动后固定额度，切换模型或修改默认值不会重置已用额度。
- 无上限只取消任务 token 限制，仍统计用量，步数限制、授权和其他执行约束仍然有效。

## 暂停与继续

发起新的模型请求前，会检查剩余额度是否足够容纳预计输入。额度不足或上一调用已超限时，任务在下次调用或工具操作前暂停，保留同一个任务、模型配置、累计用量和执行位置。

暂停面板填写的是本次任务的**新总额度**，不是追加数量。增加后点击「增加额度并继续」，或者改为「无上限」。这不会修改会话和全局默认值。也可以用停止按钮结束任务。

定时任务的运行详情同样提供预算继续入口。远程入口会提示到桌面端处理；「设置 → 通用 → 任务预算」会列出当前因预算暂停的任务。

## 边界

- 原位继续依靠仍在运行的后端保留执行现场，已完成工具不会从头重跑。**暂停期间请保持应用和后端运行。关闭、断线导致任务取消，或重启后端后，不能通过预算按钮恢复桌面任务。** 预算用量会落盘；已因预算暂停的定时任务在重启后也不会自动重放，需检查已有结果后新建任务。
- 用量优先采用供应商返回的统计；缺失时估算输入和输出。流式失败若已有返回内容，会计入可获得的部分用量；供应商未返回的消耗无法精确确认。
- 这是调用边界控制，不是供应商账单硬上限。在途请求及并行调用会先完成并入账，因此实际用量可能超过额度。若任务已经正常完成，则保留完成结果，不再要求增加预算。
- token 额度不等于金额。同样的 token 数，在不同模型、缓存命中或输入输出比例下，费用可能不同。
