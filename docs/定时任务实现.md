# 定时任务实现

本实现参考本地 OpenWorker 的 `coworker/automation/{models,store,scheduler,tools}.py` 和 `coworker/server/manager.py`。用户在工作区的「定时」页创建任务，也可让代理使用 `create_scheduled_task` 提议创建。代理创建、修改或删除计划前须由用户确认。

## 执行方式

- 计划支持一次性时间、五字段 Cron 和固定间隔，使用指定时区（默认机器本地时区）。Cron 的星期数字遵循常见约定：0/7 为周日，1 为周一。
- 后端每 30 秒检查到期任务。任务数据、下次执行时间、每次运行、事件和结果存入 `automations.db`。每个任务有独立工作目录，每次运行有独立会话 ID。
- 后端停机期间错过的计划，启动时每个任务补执行一次。前次运行未结束时，后续到点事件记为「已跳过」，不叠加执行。
- 已开始的运行若遇到进程退出，重启后沿用原运行 ID 与会话 ID。单智能体的模型决策和每个已完成的工具结果会逐步持久化；工作组中的执行节点由图检查点恢复，节点内的工具结果也会持久化。恢复时只执行尚无结果的工具调用，等待中的提问会重新出现在原运行详情中。若有非提问工具恰好在进程退出时执行，任务会停在「等待恢复确认」，由用户检查目标后决定是否重试。定时任务只能在电脑唤醒且后端运行时准时触发。
- 运行中如需用户回答问题、确认执行方案或授权工具，运行记录显示待处理卡片并保持等待状态。允许直接写入任务工作目录；其他写操作要逐次授权，或在创建时为指定工具和完全匹配的目标授予常驻权限。命令可在任务设置中按完整文本预先授权，也可在运行中的确认卡片选择「此任务以后允许这条命令」。对于完全无人值守的可信任务，可主动开启「自动批准此任务的命令与浏览器交互」：终端命令仅在该任务工作区发起时自动批准，浏览器的输入、点击、选择和上传也自动批准。命令过滤器及浏览器 URL、文件路径检查仍会执行；shell 命令本身可以访问工作区外的文件和网络。授权可在详情或编辑页撤销，修改对正在运行的任务即时生效。
- 每次运行记录最终摘要、交付文件路径及事件日志。完成和失败可在应用内提示；若配置 `lark:<chat_id>`，成功时也会把摘要发送到指定飞书会话。可从运行详情进入会话追问。

## 数据与接口

- 数据库：`MY_COWORK_AUTOMATIONS_DB`，默认位于应用数据目录的 `automations.db`。
- REST：`GET/POST /api/automations`、`GET/PATCH/DELETE /api/automations/{id}`、`POST /api/automations/{id}/run`、`GET /api/automations/{id}/runs/{run_id}`、`POST /api/automations/{id}/runs/{run_id}/cancel`。
- 旧的 `/api/schedule/jobs` 接口继续可用。启动时会尝试一次性导入旧 APScheduler 任务，也会导入启用且在技能声明中带有 `schedule` 的任务。

## 验证

在「定时」页创建一个未来两分钟的一次性任务，执行内容可写「输出当前时间和一句测试摘要」。等待运行后查看状态、摘要和运行记录；暂停一个周期任务确认不会触发；关闭后端直到计划过期，重启后确认只补执行一次。另可创建会调用 `ask_human` 的任务：卡片出现后重启后端，确认仍是同一个运行 ID，重新出现的问题可回答，并继续产出结果。可运行 `backend/tests/test_automations.py` 和 `tests/renderer/schedule-view.test.tsx` 回归核心流程。

## 目前的边界

已完成的工具调用有持久化结果，重启后不会作为待执行调用再次运行。如果进程恰好在工具已产生外部效果、但尚未写入该工具结果时退出，系统无法从本地判断外部效果是否发生，因此不会自动重试这个调用；恢复卡片要求用户先检查目标系统。运行会话中的追问使用最终摘要作为上下文，运行事件仍保留在任务详情中。外部完成通知目前只支持飞书目标。
