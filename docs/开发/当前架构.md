# 当前架构：从一次任务理解项目

> 核对日期：2026-09-28；代码基点：`f33bad9` 加本地模型与上下文改动。本文按源码说明结构，不代表已完成全部运行验收。本文含当前未提交工作区变更，不作为团队已发布能力描述。

## 先认识三个部分

MyCowork 是桌面应用。Electron 主进程负责启动本机 Python 后端、管理窗口和系统能力；React 界面负责交互；Python 后端负责组织智能体任务、调用工具、保存执行记录。

```text
用户在 React 界面输入任务
  → 界面通过本机 HTTP 请求 Python 后端
  → TaskManager 选择单智能体或工作组
  → 智能体调用模型、工具，并按执行路径处理授权
  → 事件通过 SSE 返回界面，任务结果可以包含真实文件

Electron 主进程 ── 启动/停止 Python、通过 preload 提供桌面能力
```

“本地优先”指应用和工具执行在用户机器上，并不表示所有数据都不会联网：模型和外部服务是否远程运行，取决于配置与调用。

## 共享上下文与依赖方向

`app.task_support` 放跨层使用的上下文和纯辅助函数；预算归 `app.llm`，Office 调用策略归 `app.guardrails`。旧 runtime 导入入口保留重导出，共享同一 ContextVar。底层顺序为 tools → guardrails → observability → llm → sandbox → task_support；guardrails 使用 observability 的任务标识支持审计，底层不得反向依赖业务图和运行循环，实际规则见 `.importlinter`。

## 数据和边界

- 后端数据目录由 `main.py` 的 `_data_dir` 决定：优先 `MY_COWORK_DATA_DIR`，否则为用户目录下的 `.my-cowork`；创建失败时尝试临时目录。各类 SQLite 存储的装配见 `build_stack`。
- 密钥管理见 [keychain.ts](../../electron/keychain.ts)：使用 Electron safeStorage 加密后写入 `credentials.enc`；旧 `credentials.json` 验证迁移成功后删除，已有 keytar 凭据可读取迁移。不可用时报告失败，不新增明文后备。详见[文件权限与本地存储](../使用/文件权限与本地存储.md)。
- 路径检查、工具确认和命令过滤是不同机制。不要把它们概括为操作系统级文件隔离。定时任务的授权与 shell 边界见[定时任务实现](定时任务实现.md)。
- 文件授权区分独立添加目录、当前有效的工作区绑定和当前任务内部输出。绑定撤销立即影响后续文件工具检查；显式目录保存在数据目录 `directory-permissions.json`，由 `/api/admin/whitelist` 读写。
- 打包入口见 [electron-builder.yml](../../build/electron-builder.yml)、[python_runner.ts](../../electron/python_runner.ts)。开发环境可运行，不等于安装版目录、依赖和权限已验证。

## 行业插件

可信本地 ZIP 插件在共享 Python 后端运行，Electron 生命周期协调器等待全部工作结束、停止后端、迁移并恢复数据、健康检查后开放应用。安装与恢复入口见[插件开发指南](行业应用插件开发指南.md)。维护准入与业务任务范围位于 `app.task_support.admission`、`app.task_support.app_context`；预算暂停任务继续占用准入名额。

业务 AI 复用 TaskManager 的模型快照、预算、工具循环和确认机制，并保留插件工具/技能/文件范围。原有模型热同步、上下文压缩和记忆流程保留；桌面本地 HTTP/SSE 统一经过带认证的主进程代理。插件执行记录在 TaskStore 持久保存，重启只恢复展示，不重放未完成任务。
