## 关键选择的理由从哪里来

这里只摘取旧文的设计意图，避免把整段调研结论复制为现行事实。

| 选择 | 原文记录的主要理由 | 当前能确认的范围 |
|---|---|---|
| Electron + 本机 Python | 直接操作办公文件，复用 Python 文档生态；接受打包成本 | [落地方案](../历史/落地方案.md) §1.2、§4.4；当前仍有这两个运行部分 |
| 模型可替换 | 避免绑定单一供应商，控制成本 | 同上 §1.2、§9；[gateway.py](../../backend/app/llm/gateway.py) 同时有 Anthropic 和 OpenAI 兼容入口，并非只支持一种协议 |
| 应用内授权与审计 | 减少虚拟机带来的文件交换成本 | 同上 §4.3；当前有护栏，但不同工具、渠道和自动化任务的授权行为需分别核对 |
| 本机调度 | 不依赖集中服务，接受机器停机期间不能执行 | 同上 §8.3；当前恢复与补执行行为见[定时任务实现](定时任务实现.md) |
| 复用外部知识库 | 避免再建一套 RAG 产品 | [知识库集成方案](../历史/知识库集成方案.md) §1；目前接入范围见上表 |
