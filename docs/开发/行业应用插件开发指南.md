# MyCowork 行业应用插件开发指南（v1）

本文说明如何开发、打包和安装能在 MyCowork「行业工作台」中运行的行业应用。当前插件类型为 Python 后端加静态 Web 页面，适合任务管理、轻量 ERP 扩展、行业表单和本地业务台账等应用。

本文对应当前仓库中的实现。开发前可先运行 [任务管理样例](../../examples/taskboard/README.md)，协议细节以 [包校验器](../../backend/app/industry_apps/package.py)、[加载器](../../backend/app/industry_apps/loader.py) 和 [工作台页面](../../renderer/src/components/hub/IndustryWorkbench.tsx) 为准。后续演进方向见 [实现方案](./行业应用包与工作台实现方案.md)。

## 1. 运行模型

一个插件 ZIP 包含：

- 根目录的清单和校验表；
- 一个具有独立名称的 Python 包，提供 FastAPI 路由；
- 一个已构建的静态 Web 页面，显示在工作台内。

安装时，宿主检查 ZIP 路径、文件大小、清单和每个文件的 SHA-256。确认安装后，宿主等待当前工作结束，保存数据恢复点并自动启用；无需手动重启后端。后端启动时导入插件的 Python 入口，将其路由挂到 /api/apps/{应用 ID}；页面则通过 mycowork-app:// 协议加载到 iframe 中。页面调用后端时，使用工作台提供的 postMessage 桥接。

**信任边界：** Python 代码在 MyCowork 现有后端进程内执行，可访问该进程的 Python 环境和操作系统资源。当前版本没有进程级隔离。请只安装来源可信、经过审查的应用。页面有独立来源、资源访问限制和受控桥接，但这不能隔离后端 Python 代码。

## 2. 开发环境与目录

当前宿主使用 Python 3.11 或 3.12。前端可以使用任意框架或原生 HTML、CSS、JavaScript，交付物必须是无需开发服务器的静态文件。插件安装器不会执行 pip、npm，也不会为每个插件创建单独的 Python 虚拟环境。

推荐目录如下。以下示例的应用 ID 是 cn.example.taskboard，因此 Python 根包名称是 mcapp_cn_example_taskboard。

~~~text
taskboard/
├── mycowork-app.yaml
├── backend/
│   └── mcapp_cn_example_taskboard/
│       ├── __init__.py
│       ├── plugin.py
│       └── storage.py              # 可选
└── frontend/
    └── dist/
        ├── index.html
        ├── app.js
        ├── style.css
        └── assets/                 # 可选；图片、字体等本地资源
~~~

打包脚本会在 ZIP 根目录自动生成 checksums.sha256。不要手工维护该文件。测试、构建缓存、node_modules、开发文档等建议放在插件源码目录之外，避免被打进 ZIP；当前打包脚本会收集源码目录下除 __pycache__、.pyc 和 checksums.sha256 以外的普通文件。

### 必需路径

| 路径 | 作用 |
| --- | --- |
| mycowork-app.yaml | 插件清单，必须位于 ZIP 根目录 |
| backend/mcapp_<ID 中点号改为下划线>/__init__.py | Python 包标识 |
| frontend/dist/index.html | 页面入口 |
| checksums.sha256 | 每个其他 ZIP 文件的 SHA-256，由打包脚本生成 |

ZIP 不应在这些文件外再套一层目录。例如 ZIP 第一层应直接看到 mycowork-app.yaml，而不是 taskboard/mycowork-app.yaml。backend/ 下的文件必须全部位于该应用自己的 mcapp_ 根包之内。

## 3. 清单规范

可直接使用以下清单作为起点：

~~~yaml
schema_version: 1
id: cn.example.taskboard
name: 任务管理样例
version: 1.0.0
description: 带独立页面与 SQLite 数据的本地任务管理应用
min_host_version: 0.0.9
sdk_version: 1
kind: python-web
platforms: [darwin-arm64, darwin-x64, win-x64]
backend:
  entry: mcapp_cn_example_taskboard.plugin:register
  requires_python: ">=3.11,<3.13"
ui:
  entry: frontend/dist/index.html
  route_mode: hash
  bridge_version: 1
  min_width: 640
data:
  scope: workspace
capabilities:
  host_api: []
  network_domains: []
agent_tools:
  - name: list_items
    title: 查询条目
    description: 查询此应用中的条目。
    access: read
skills: []
~~~

| 字段 | 当前 v1 规则 |
| --- | --- |
| schema_version | 1 保持兼容；显式数据迁移与健康检查使用 2（见下文） |
| id | 必填；反向域名形式的小写字母和数字，以点号分段，例如 cn.example.erp；每段首字符必须是小写字母 |
| name | 必填，1～80 个字符 |
| version | 必填，数字 MAJOR.MINOR.PATCH，例如 1.2.0；不接受预发布后缀 |
| description | 可选，最多 500 个字符 |
| min_host_version | 可选，数字 MAJOR.MINOR.PATCH；宿主版本低于此值时拒绝安装 |
| sdk_version | 只能为 1 |
| kind | 只能为 python-web |
| platforms | 可选；空数组表示不限定；当前识别 darwin-arm64、darwin-x64、win-x64 |
| backend.entry | 必填，形式为 模块:函数；模块必须属于该应用的 mcapp_ 根包 |
| backend.requires_python | 只能写 ">=3.11,<3.13" |
| ui.entry | 只能写 frontend/dist/index.html |
| ui.route_mode | 只能为 hash |
| ui.bridge_version | 只能为 1 |
| ui.min_width | 可选，范围 320～1920；当前清单可保存此值，工作台暂未据此调整 iframe 宽度 |
| data.scope | 可选，workspace 或 global；当前推荐 workspace |
| data.migration_entry | v1 不填写；v2 改变数据版本时指定本插件命名空间内的 `module:function` |
| capabilities.host_api | 按需声明 ai、files、navigation、ui；未声明的能力不能调用 |
| capabilities.network_domains | 当前必须为空数组 |
| agent_tools | 可选，最多 32 项；声明 Agent 可调用的工具名称、标题、描述及 read/write 权限；运行时贡献必须逐项匹配 |
| skills | 随包技能目录列表，例如 `[skills/risk-analysis]`，详见 A3 |

清单会拒绝未知字段。建议只写需要的可选字段。ID 发布后应保持稳定：它同时决定 Python 包名、后端路由前缀、页面来源和数据目录。更新已有应用时保留 ID，递增 version。

平台选择只是安装时的兼容性声明。若代码仅使用宿主已有的纯 Python 依赖，通常可以省略 platforms；若代码确实依赖某个平台的行为，应显式列出已验证的平台。当前 ZIP 不支持附带 .so、.pyd、.dll、.dylib 或 .pyc。

## 4. Python 后端接口

入口函数签名为 register(context: AppContext) -> AppContribution。函数应创建并返回 FastAPI APIRouter，由宿主添加应用专属前缀。不要在路由里重复写 /api/apps/{应用 ID}。

~~~python
from fastapi import APIRouter
from pydantic import BaseModel, Field

from app.industry_apps.sdk import AppContext, AppContribution, AppTool, AppToolCallContext


class ItemInput(BaseModel):
    title: str = Field(min_length=1, max_length=200)


class ListItemsArgs(BaseModel):
    limit: int = Field(default=20, ge=1, le=100)


def register(context: AppContext) -> AppContribution:
    router = APIRouter()

    @router.get("/items")
    def list_items() -> dict:
        return {"items": []}

    @router.post("/items")
    def create_item(body: ItemInput) -> dict:
        return {"title": body.title}

    def agent_list_items(_call: AppToolCallContext, args: ListItemsArgs) -> dict:
        return {"items": [], "limit": args.limit}

    return AppContribution(router=router, tools=[AppTool(
        name="list_items",
        title="查询条目",
        description="查询此应用中的条目。",
        args_schema=ListItemsArgs,
        run=agent_list_items,
        access="read",
    )])
~~~

假设 ID 为 cn.example.taskboard，示例中的实际路径是 GET /api/apps/cn.example.taskboard/items 和 POST /api/apps/cn.example.taskboard/items。页面桥接请求只传相对应用路由的 /items。

AppContext 当前提供：

- app_id：清单中的应用 ID；
- data_root：应用数据根目录，供内部实现使用；
- workspace_data_dir(workspace_id)：创建并返回此应用在指定工作空间的数据目录。

workspace_id 不能为空，不能是 . 或 ..，也不能包含斜杠或反斜杠。当前 SDK 没有提供取得宿主当前工作空间 ID 的方法；插件应在自己的 API 请求中明确传入业务上选定的工作空间 ID。样例使用 local 作为默认值。不要把用户任意输入直接拼接到数据文件路径。

### Agent 工具贡献

`AppContribution.tools` 可贡献 `AppTool`，供聊天 Agent 直接调用；仍不支持 `jobs`。ZIP 的 `agent_tools` 声明与 Python 贡献的 `name`、`title`、`description`、`access` 必须完全一致，否则应用加载失败。工具名称只能用小写字母、数字和下划线，宿主会自动加 `industry__<应用 ID 下的点号改为下划线>__` 前缀，避免与普通工具重名。安装页会列出这些工具；聊天输入框的“行业工作台工具”入口将它们与连接器、技能分开列出，选中后插入使用提示。聊天执行记录也会显示“行业工作台”、应用名称和工具标题。

工具参数必须是 Pydantic `BaseModel`，处理函数接收 `AppToolCallContext` 和已校验的参数实例；可用同步或异步函数。`AppToolCallContext` 由宿主提供 `app_id`、`space_id`、`project_id`、`task_id`，不能由模型伪造。只读工具适合任务查询和工时统计。写入工具声明 `access: write` 后，宿主在桌面端执行前请求用户确认；拒绝时不会调用处理函数。远程聊天没有桌面确认入口时，行业应用写入调用会被拒绝。不要在只读工具中修改业务数据。ZIP 中的 Python 仍是可信进程内代码，`read/write` 声明用于权限交互和审查，不构成操作系统沙箱。

工具会在后端启动时注册到单智能体和协作智能体。安装、更新、停用或启用由宿主等待工作结束并自动切换；只有已启用且加载成功的应用提供工具。为了让 Agent 准确选用工具，描述应说明查询范围、字段和副作用。返回值宜使用简短、可序列化的 `dict` 或字符串，并对列表结果设置上限；不要返回整库或大量隐私数据。

### 编码约束

1. **入口要轻量。** register 在后端启动期间同步执行；避免在导入模块或注册路由时做大规模扫描、长时间迁移、网络请求或无限循环。
2. **路由要有清晰的数据模型。** 使用 Pydantic 校验输入长度、类型和必填字段；为不存在的资源返回适当的 HTTP 错误。
3. **依赖必须由宿主提供。** 当前安装过程不会解析 requirements.txt。优先使用 Python 标准库以及宿主已包含的 FastAPI、Pydantic 等依赖；新增依赖应先进入宿主的打包与兼容性流程。
4. **业务数据写入数据目录。** 安装目录按版本存储代码和页面；业务数据库、上传文件等应放在 context.workspace_data_dir(workspace_id) 下，避免更新或回退时丢失。
5. **数据库访问要可维护。** 轻量应用可以使用 sqlite3；SQL 参数使用占位符，连接及时关闭，写入显式提交。不同请求并发访问时须按数据库规则处理事务和锁。
6. **异常要可诊断。** 在接口层返回明确错误；不要把令牌、数据库密钥或用户隐私写入异常消息与日志。
7. **不要改动宿主全局状态。** 避免修改 sys.path、全局路由、宿主配置、其他插件目录或系统环境变量；加载器负责导入与路由挂载。

这些编码约束中，第 1、2、4～7 项是开发建议；ZIP 校验与入口返回值的限制由代码强制执行。由于插件与宿主共用进程，编码质量会直接影响整个后端的稳定性。

## 5. 页面与前后端桥接

页面入口固定为 frontend/dist/index.html。工作台会把它加载到 iframe 中，页面静态资源通过 mycowork-app://{应用 ID}/ 路径提供。HTML 中用相对地址引用脚本、样式和图片，例如 ./app.js、./style.css；前端路由使用 hash 模式。构建工具需要生成可直接从该入口加载的静态资源，避免依赖开发服务器或绝对站点根路径。

当前页面的资源策略允许同来源脚本、样式、字体和图片，以及 data: 图片；禁止内联脚本、内联样式和页面直接连接网络（包括 fetch 与 WebSocket）。请把脚本和样式输出为独立文件。页面也不能直接调用宿主 Electron API。业务请求必须走 postMessage 桥接，由工作台转给应用自己的后端路由。

桥接请求格式：

~~~js
{
  channel: "mycowork-app/v1",
  appId: "cn.example.taskboard",
  bridgeToken: "...",          // 从 index.html?bridge=... 读取
  id: "request-1",             // 当前页面内唯一的请求 ID
  type: "request",
  operation: "app.request",
  method: "GET",
  path: "/items",
  body: undefined
}
~~~

桥接响应包含相同的 channel、appId、bridgeToken、id，type 为 response；成功时 ok: true 且 data 为后端返回的 JSON，失败时 ok: false 且 error 为错误文本。允许的方法为 GET、POST、PATCH、PUT、DELETE。path 以 / 开头，可以包含查询参数，但不能包含路径穿越、反斜杠、片段标记或编码后的斜杠。请求最终只会到本应用的 /api/apps/{应用 ID} 前缀。

一个最小可用的页面调用封装：

~~~js
const channel = "mycowork-app/v1";
const appId = "cn.example.taskboard";
const bridgeToken = new URLSearchParams(location.search).get("bridge");
const pending = new Map();
let nextId = 0;

window.addEventListener("message", (event) => {
  if (event.source !== window.parent) return;
  const message = event.data;
  if (
    !message ||
    message.channel !== channel ||
    message.appId !== appId ||
    message.bridgeToken !== bridgeToken ||
    message.type !== "response"
  ) return;
  const item = pending.get(message.id);
  if (!item) return;
  pending.delete(message.id);
  clearTimeout(item.timer);
  if (message.ok) item.resolve(message.data);
  else item.reject(new Error(message.error || "请求失败"));
});

function request(method, path, body) {
  if (!bridgeToken) {
    return Promise.reject(new Error("请从 MyCowork 工作台打开此应用"));
  }
  return new Promise((resolve, reject) => {
    const id = String(++nextId);
    const timer = setTimeout(() => {
      pending.delete(id);
      reject(new Error("宿主响应超时"));
    }, 15000);
    pending.set(id, { resolve, reject, timer });
    window.parent.postMessage({
      channel, appId, bridgeToken, id,
      type: "request", operation: "app.request",
      method, path, body
    }, "*");
  });
}

request("GET", "/items").then(console.log);
~~~

这里使用 * 作为发送给父窗口的目标来源，是因为宿主页面在不同运行方式下可能有不同来源。工作台会检查发件 iframe、来源、应用 ID 和 bridgeToken；插件页面收到响应时也应检查 event.source、应用 ID、令牌和请求 ID。令牌只用于这条页面消息通道，不代表插件获得了任意宿主 API 权限。

界面开发建议：

- 给加载、空列表、失败和提交中状态提供清晰反馈；
- 用户内容用 textContent 或安全的框架文本插值渲染，避免直接拼进 innerHTML；
- 页面应适应工作台容器宽度和约 600 像素起的高度；
- 将脚本、样式、图片和字体一起打包，不引用 CDN；使用 Vite 等构建工具时配置相对资源基路径（例如 ./）；
- 完成构建后从 frontend/dist/index.html 检查相对资源路径。

## 6. 数据、升级和版本

默认安装根目录为 MyCowork 数据目录下的 industry-apps；通常位于 ~/.my-cowork/industry-apps。开发或测试时可用 MY_COWORK_INDUSTRY_APPS_ROOT 覆盖。主要路径：

~~~text
industry-apps/
├── registry.db
├── packages/
│   └── cn.example.taskboard/
│       ├── 1.0.0/
│       └── 1.1.0/
└── data/
    └── cn.example.taskboard/
        └── local/
            └── tasks.db
~~~

注册表记录当前已激活版本、候选版本、数据版本、操作阶段和恢复点。旧 registry.json 首次读取时事务导入，保留原件但不再使用它作为运行状态。暂存不会改变运行版本；候选加载与检查成功后才提交。页面资源、桥接和 Agent 工具属于同一次后端运行，旧页面不能请求新一代接口。

插件卡片和页面标题栏菜单提供「从 ZIP 更新」「停用/启用」「恢复上次更新」「移除」。目前没有在线市场或自动版本发现，作者通过自己的渠道分发新版 ZIP。更新前要保存插件页面中的草稿；平台不能识别 iframe 内未保存的内容。等待阶段可取消更新，现有任务继续；正在保存或切换时由宿主完成或恢复。移除保留业务数据，重装继续检查数据兼容性。

最近一次成功更新前的程序与数据构成配套恢复点。主动恢复会保留当前数据副本，再回到恢复点时间的记录，不自动合并两份数据。详情可查看保留副本的位置。未提交的迁移/注册/健康检查失败会恢复原数据；已提交的新版本不会因后续故障自动覆盖新记录。恢复失败时保留各份数据，工作台可重试或停用故障插件。

### 清单 v2：显式数据迁移

SDK 和页面桥接版本仍为 1，清单 schema_version 改为 2。此分支的宿主版本为 0.1.1；该数字不是宣称团队原版 0.1.1 已有 v2 能力。共同发版时应同步更新实际宿主版本与包的 min_host_version；旧安装器会明确拒绝 schema_version 2。

```yaml
schema_version: 2
min_host_version: 0.1.1
backend:
  entry: mcapp_cn_example_taskboard.plugin:register
  health_entry: mcapp_cn_example_taskboard.migrations:check
data:
  scope: workspace
  version: 1
  upgrade_from: [legacy]
  migration_entry: mcapp_cn_example_taskboard.migrations:migrate
```

- `data.version` 为整个插件的数据格式正整数；旧 v1 数据标记为 `legacy`，不能假定其格式版本为 1。
- 改变数据格式或接纳 legacy，必须在 `upgrade_from` 中明确列出来源并提供迁移入口；同一数据版本跳过迁移。首次空目录安装由 register 初始化。
- `migrate(context)` 接收 `app_id`、`data_root`、`source_version`、`target_version`、`source_data_version` 和 `target_data_version`，一次处理全部已有空间。作者负责识别旧表结构和业务转换。
- `check(context)` 是必填同步只读健康检查，接收 `AppContext`；在注册成功后执行。不得调用 AI、网络或修改业务记录，失败抛出异常。
- 迁移在可终止的独立进程中执行，超时 60 秒。候选注册与检查受后端启动总超时限制。失败重试从恢复后的数据开始，不续跑半次脚本。

平台先暂停接入，等待任务、插件请求和实际工具线程退出，再停止后端。确认独占运行锁后复制整个 `data/{id}`，包括 SQLite WAL/journal，核对文件哈希并在副本上检查 SQLite。自动恢复只保证托管目录中插件独占的普通文件及未加密 SQLite，不包含外部文件、独立子进程、外部数据库或服务；可信 Python 不是安全沙箱。作者必须避免导入和迁移产生这些不可恢复副作用。

可用样例：保留 `examples/taskboard` 的 v1 包，然后用后端 Python 执行 `examples/taskboard/make-upgrade.py OUTPUT.zip`，生成 1.1.0/v2 包。其迁移为全部已有空间的 tasks 表增加 note 字段，健康检查用只读连接检查结构；正常新建数据库也包含该字段。

开发模式由桌面拥有单一 Python 进程，防止 reloader 绕过生命周期锁。后端源码修改后通过宿主的重启入口应用；前端 Vite 热更新不受影响。管理与恢复的维护命令不依赖模型服务，尚未配置模型时可以保存包，配置后再启用。


## 7. 打包、检查与安装

在仓库根目录执行：

~~~sh
python3 scripts/pack-industry-app.py examples/taskboard -o /tmp/taskboard-1.0.0.zip
~~~

将 examples/taskboard 换成自己的插件源码目录。输出 ZIP 必须放在源码目录之外。脚本使用固定文件顺序和时间戳，并生成 checksums.sha256；同样的文件内容可得到稳定的包。校验表用 UTF-8 编码，每行是 64 位小写十六进制 SHA-256、两个空格、ZIP 内相对文件路径，且必须恰好覆盖除校验表自身以外的所有文件。该校验表用于检测文件变化，不提供作者身份认证。

本地可用当前后端的校验器检查包：

~~~sh
PYTHONPATH=backend backend/.venv/bin/python -c 'from pathlib import Path; from app.industry_apps.package import inspect_zip; print(inspect_zip(Path("/tmp/taskboard-1.0.0.zip").read_bytes()).public())'
~~~

若本地虚拟环境路径不同，用运行 MyCowork 后端的 Python 3.11/3.12 环境执行，并确保已安装宿主依赖。

在 MyCowork 中打开「行业工作台」→「安装 ZIP」，选择包并查看名称、版本、ID 和文件数量。确认来源可信后安装，等待自动启用。状态显示「可用」后打开应用。安装前检查和实际安装会对同一个 ZIP 计算 SHA-256；如果文件在两步之间发生变化，安装会被拒绝。

### ZIP 限制

| 项目 | 上限或规则 |
| --- | --- |
| ZIP 文件大小 | 50 MiB |
| 解压后总大小 | 200 MiB |
| 单文件大小 | 50 MiB |
| 清单大小 | 64 KiB |
| ZIP 条目数量 | 1000 |
| 单文件解压比 | 不超过 1000 |
| 路径 | 相对路径；禁止上级跳转、重复路径、反斜杠、符号链接和设备文件 |
| 文件完整性 | checksums.sha256 必须覆盖除此文件之外的每一个文件 |
| 二进制内容 | 不接收原生扩展库及 Python 字节码 |

## 8. 开发验证清单

1. 清单 ID、Python 根包目录名、backend.entry 和页面代码中的 appId 一致。

3. 用打包脚本生成 ZIP，并用 inspect_zip 成功检查。

5. 应用使用自己的数据目录，关闭和重启后端后数据仍可读取。
6. 使用测试数据验证从旧版本升级，以及必要时手动回退。
7. 在准备声明的平台上实际运行并检查后端日志与工作台状态。

仓库中的 [任务管理样例](../../examples/taskboard/) 提供完整的清单、SQLite 路由和页面桥接实现，可作为新插件的起点。复制时应同步修改 ID、Python 包名、清单入口和页面 appId。

## 9. 常见问题

**提示 invalid manifest：** 检查未知字段、版本格式、Python 范围、平台声明及 capabilities、skills 的支持范围；migration_entry 只在 v2 开放。v1 不会忽略不支持的权限申请。

**提示 missing backend/.../__init__.py：** Python 根包名必须精确对应应用 ID，把点号替换为下划线并加 mcapp_ 前缀；ZIP 根目录也不能多套一层。

**安装后页面打不开：** 先确认状态为「可用」；「待启用」先配置模型再启用，「需要恢复」通过菜单重试恢复或停用。检查前端构建产物的入口和相对资源路径。

**页面请求失败：** 确认页面从工作台打开，bridgeToken 存在，appId 一致；桥接 path 写 /items 这类应用内路径，不要自行添加 /api/apps/{应用 ID}。页面直接 fetch 后端会被资源策略阻止。

**依赖导入失败：** 当前 ZIP 安装不会 pip install。检查该依赖是否已由宿主后端提供；否则需要先完成宿主依赖与打包适配。

**更新后数据异常：** 先保留现场并检查迁移与健康检查。使用「恢复上次更新」会配套恢复程序和当时的数据；当前记录另存副本，不应假定新旧数据会自动合并。
## 从业务页面使用宿主 AI（A2）

此能力随当前行业平台升级提供，发布时需指定包含 A1/A2 的新宿主版本；不能将团队旧版 0.1.1 视为已经支持。插件仍是可信进程内 Python 代码，不是恶意代码沙箱。

在 `capabilities.host_api` 中按需声明 `ai`、`files`、`navigation`、`ui`。宿主在安装确认中展示这些能力。声明不会给予任意文件、其他插件或通用后端访问权；模型配置和认证令牌由宿主管理。

沿用 `mycowork-app/v1` 消息封套：`channel`、`appId`、页面 URL 中的 `bridgeToken`、唯一 `id`、`type: "request"` 和 `operation`。请求 ID 使用 UUID 或不超过 100 字符的字母、数字、下划线、连字符。宿主校验当前 iframe、来源、插件身份和能力。响应为同一 `id` 的 `type: "response"`，包含 `ok` 和 `data` 或 `error`。插件只使用父窗口桥接，不能直接调用 localhost API。

| operation | 请求字段 | 行为 |
|---|---|---|
| `ai.startTask` | `body: { prompt, context, tools, skills?, files?, produce_file? }` | 返回已接收的任务记录；宿主绑定应用版本、运行代次、空间、会话和执行 ID，不切换工作区 |
| `ai.listTasks` | 无 | 列出本插件执行记录 |
| `ai.getTask` | `task_id` | 获取所属任务的状态、执行事件、文件引用和实际业务操作结果 |
| `ai.stopTask` | `task_id` | 请求停止；已经执行的写入不会回滚 |
| `ai.openTask` | `task_id` | 打开宿主业务页覆盖详情，不改变业务页面宽度 |
| `files.pick` | 无 | 用户选择文件，返回 `{ files: [{ id, name }] }`，不提供任意路径读取接口 |
| `files.open` | `file_id` | 打开本插件已登记的文件；文件移动或删除时明确报错 |
| `navigation.setRoute` | `route` | 保存以 `/` 开头的本插件内部返回位置；不会导航当前 iframe |
| `ui.setDirty` | `dirty: boolean` | 声明未保存内容；宿主离开或刷新前提示。草稿内容仍由插件保存 |

发起示例（封套字段略）：

```js
{
  operation: "ai.startTask",
  body: {
    prompt: "分析所选任务的交付风险",
    context: { partition: "local", selection: [12, 18] },
    tools: ["list_tasks"],
    files: [],
    produce_file: false
  }
}
```

`tools` 使用本插件 manifest 中的业务工具短名。分析只请求需要的只读工具；写入动作才包含对应写工具。模型只能看到并执行这个有效工具集合，以及宿主的补充提问能力。通用 shell、任意文件读写、其他插件、MCP 和全局记忆工具不会因为进入工作区而加入。后续追问继承原业务范围；若需要扩大范围或应用版本已变化，应返回业务页重新选择并发起。

业务范围通过 `AppToolCallContext.business` 传入 Python 工具。工具必须根据自己的业务规则验证分区、选中对象和对象是否仍存在；平台不会猜测行业字段。宿主 `space_id` / `project_id` 与插件数据分区不同，不能直接用宿主空间替换既有 `local` 数据。`examples/taskboard` 展示了页面和 AI 工具读取同一分区，并验证创建子任务的父对象属于选择范围。

文件首段支持用户选择的 UTF-8 TXT、Markdown、CSV、JSON，单文件最大 2 MB，每次任务最多 10 个引用。`produce_file: true` 额外提供 `app_write_report`，将完整内容保存为新的 Markdown 产物。它不开放 shell 或任意输出路径；暂不提供通用 Office 文档生成接口。文件引用归属由宿主验证，不能自行构造文件路径作为引用。

重复传递同一个请求 ID 和相同内容会返回同一执行，内容不同则拒绝；明确重新发起应使用新 ID。关闭详情、刷新插件和页面往返不停止宿主任务。宿主通过 `host.ai.changed` 通知所属任务变化，通知只作提醒，插件恢复后应查询记录。业务列表应在操作结果返回后刷新，不能把“允许操作”或模型文字当作数据库写入成功。

详情与工作区共用会话展示，问题和确认只能由宿主用户界面处理，插件不能代用户批准。任务记录与事件由后端保存，窗口重开可恢复；后端重启将未结束执行标为 `INTERRUPTED`，不会自动重放写操作。停止同步写操作时，宿主继续记录它实际完成或失败的结果；中断后没有返回结果的操作必须检查真实业务记录。

运行中可以请求 A1 更新或停用：维护等待期间已有任务仍可回答、确认、拒绝和停止，新任务被拒绝。应用切换代次后旧页面不能继续发起，原记录保留版本和来源。应用移除、文件失效、业务对象删除都不应伪装为返回成功。


## 随包行业技能（A3）

需使用包含 A3 的新宿主版本。插件清单的 `skills` 声明包内目录，例如：

```yaml
skills:
  - skills/risk-analysis
  - skills/weekly-report
```

每个目录包含且仅包含一个 `SKILL.md` 或 `skill.yaml`。目录名为小写字母开头的 1–64 位字母、数字、下划线或连字符，最多 32 个。`SKILL.md` 使用 YAML frontmatter 的 `name`、`description` 与 Markdown 正文；`skill.yaml` 使用 `name`、`description`、`prompt`。显示名称可以相同，身份来自目录短名。入口 UTF-8 不超过 64 KiB，正文非空且不超过 16000 字符，名称最多 100、描述最多 1000 字符；超长说明拆到资料文件。禁止 schedule；allowed_tools、params 元数据即使存在也不授予权限。

```markdown
---
name: 任务风险分析
description: 按选中任务证据检查风险
---
先使用 read_skill_resource 读取 references/evidence.md，再核对选中任务。
没有提供的截止时间、责任人和进度标为待确认，不要编造。
```

业务请求 `ai.startTask` 的 `body.skills` 使用该插件声明的短名，例如 `skills: ["risk-analysis"]`。可省略/为空，最多 8 项，去重后按选择顺序载入，可在不同按钮间共用。宿主只加载这组技能，不根据 Office 关键词增加或删除；格式化后的正文总计最多 64000 字符，超限明确拒绝，不静默截断。选择无法解析、停用或版本不匹配的技能时，在创建任务前拒绝。

宿主将当前版本正文随 AI 请求载入。资料按需读取：`read_skill_resource(name="app:cn.example.taskboard:risk-analysis", path="references/evidence.md")`；每次最多 64 KiB UTF-8，支持 md/txt/csv/json/yaml/yml，路径限于该技能目录，禁止链接与越界。业务任务只能读取本次所选技能。首段不运行技能 scripts，也不因技能文字增加业务写入、文件或 shell 权限；所有操作沿用 A2 的实际工具限制和用户确认。

随包技能不会复制到用户技能目录；安装时展示名称，Skills 卡片展示所属插件及版本，通过所属插件统一管理，不能单独修改/删除/启停。暂存候选不会替换当前技能；成功切换、回退、停用随 A1 生命周期生效。普通聊天沿用技能选择器，以 `#app:<插件ID>:<短名>` 保留身份，使用当前可用版本，不恢复历史技能版本。

AI 详情与工作区显示本次实际载入的技能和版本，后端 `loaded_skills` 来自执行时保存的事件；请求已接收但尚未载入时为空。同版本追问继承原技能集合，版本变化后返回业务页重新发起。说明正文及资料是方法指导，不是额外授权。样例的风险分析、周报是平台能力演示，尚不是经过行业验收的标准。

## 本地开发工具（A4）

工具随本仓库提供，需先按[开发指南](开发指南.md)准备对应宿主的 Node、前端依赖和 backend/.venv。此分支的本地 0.1.1 包含未发布的平台升级，团队旧版 0.1.1 不具备这些能力。首版没有独立 npm/PyPI 发布，也不自动安装插件 Python 第三方依赖。

在宿主仓库执行以下命令（Windows 使用 npm.cmd）：

```powershell
npm run app -- init "C:/projects/库存管理" --id cn.example.inventory --name 库存管理
cd "C:/projects/库存管理/frontend"
npm install
cd "<宿主仓库>"
npm run app -- dev "C:/projects/库存管理"
```

也可在宿主仓库执行 npm link，将 mycowork-app 链接为本地命令；不链接时继续使用 npm run app --。生成项目是 React/TypeScript/Vite、SQLite 记录接口和 schema v2 清单。身份、Python 包名和页面身份已配套，非空目标目录会拒绝覆盖。SDK 用本地 file 依赖连接当前宿主源码，升级工具后需重新安装插件前端依赖。

dev 启动独立 Electron/共享 Python 后端及本项目回环 Vite 服务。开发数据位于 ~/.mycowork-app-dev/<项目路径摘要>/source，安装验证位于同摘要下的 package-test；日志位置在终端显示。终端继承的宿主目录、模型/渠道配置与密钥环境会清理；系统凭据服务也使用独立作用域。首次在该实例配置自己的模型，不读取日常实例密钥。既有宿主终端环境首次准备仍会安装宿主约定的工具依赖。自动调度和外部渠道停用，不改日常实例。

在工作台打开应用，同时在自己的编辑器改代码。前端文字/样式保存后热更新；后端、清单、技能保存后输入 r 受控重载，c 取消维护等待，q 等已有工作完成后退出。未配置模型时显示等待配置。页面草稿由模板 sessionStorage 保留；请在重载前保存业务内容，平台不自动保存任意页面输入。数据和日志在退出后保留，重复启动继续使用；同一开发目录拒绝重复实例。

Python 和技能运行于检查后的不可变快照。正式版本不变也能重载，未变化则跳过；失败沿用平台备份、恢复和运行代次检查。AI 记录显示开发修订，跨修订追问需从业务页重新发起。退出取得维护锁后，只清理无引用的旧源码快照，当前/候选/恢复/未完成操作引用继续保留；不清理业务数据与恢复副本。清理失败保留快照并在日志说明。

```powershell
npm run app -- validate "C:/projects/库存管理"
npm run app -- pack "C:/projects/库存管理" -o "C:/projects/inventory-1.0.0.zip"
npm run app -- validate "C:/projects/inventory-1.0.0.zip"
npm run app -- dev "C:/projects/库存管理" --package-test
```

validate 只检查已有 dist 或 ZIP，不构建、不导入插件代码。pack 先执行生成项目约定的 frontend build，失败不使用旧 dist；静态插件直接收集已有 dist。输出须在源码目录外，默认不覆盖。最终 ZIP 使用安装器同一检查规则，并输出实际文件、数量与展开体积。收集清单、命名空间后端、dist 和声明的技能；排除缓存、依赖、测试目录、日志、数据库、.env 与常见凭据文件。请核对输出清单，勿将秘密硬编码入业务源文件。

package-test 不挂源码或 Vite，通过工作台安装刚生成的 ZIP，使用正式静态协议和原 CSP。必须实际检查资源、接口、刷新和已有数据更新；data.version 变化应提高正式版本并声明 upgrade_from，在这里测试迁移和失败恢复，不能在源码 dev 中清空数据代替验收。检查通过只表示当前宿主/平台接受包，不等于业务、真实模型或其他操作系统验收。

### 页面 SDK

生成页面从 @mycowork/app-sdk 导入 createHost({ appId })，生产构建将 SDK 并入相对静态资源，ZIP 无外部 SDK 路径依赖。API 为 request、ai、files、navigation、ui、on 和 dispose，具体参数沿用前述 v1 桥接。SDK 校验父窗口、精确来源、令牌和应用身份；普通请求默认 30 秒，文件选择 5 分钟。超时或断开表示结果尚未确认，不自动重放写入，应查询实际记录。

模块热替换调用 import.meta.hot.dispose(() => host.dispose())；组件注销 on 返回的监听器。刷新或后端切换后新页面重新建立连接，旧连接待响应请求在 dispose 时结束。普通静态页面可用 pagehide 注销。示例 taskboard 的 sdk.js 由同一源码生成，修改 SDK 后运行 node examples/taskboard/build-sdk.cjs；生成的 Vite 项目不需要此步骤。

Windows 已完成本地开发与安装验证；macOS、完整安装器与真实模型效果仍需各自验收。

## 宿主模型与任务预算

业务页首次发起使用宿主默认模型和全局预算。展开到工作区后，可以选择该会话的模型、思考强度和预算；追问使用这些设置。每次执行固定启动时的配置，修改模型不重启后端、不改变已运行任务。插件 SDK 不接收或暴露凭据与宿主模型选择。

预算不足时，原任务保持暂停，宿主详情或工作区可增加额度继续，也可停止。维护排空会等待这类任务；等待期间可以继续任务或取消更新。后端重启后不自动重放未完成的业务操作。
