# MyCowork 开发指南

## 本地开发

```bash
# 依赖
cd backend && uv sync
cd .. && npm install

# 一键（Vite + tsc watch + Electron）
npm run dev
```

也可分终端：

```bash
npm run dev:renderer   # Vite :5174
# 另开：配置 MY_COWORK_API_KEY 后
cd backend && uv run uvicorn app.main:app --port 8765
npm run dev:electron
```

## 测试

```bash
# 后端
cd backend && PYTHONPATH=. uv run pytest -q
cd backend && PYTHONPATH=. uv run lint-imports

# 前端 / Electron 单测
npm test

# Playwright e2e（需先 build）
npm run test:e2e
```

## 分层契约（import-linter）

契约定义在 `backend/.importlinter`。新增模块时：

- 业务层不要反向依赖 `server` / `orchestrator`
- `sandbox` / `llm` / `guardrails` / `observability` 遵守 forbidden 规则
- 装配只放在 `app.main`

## 添加 Skill

1. 新建 `skills/<id>/skill.yaml`（`id`、`allowed_tools`、可选 `schedule`、`prompt`）
2. 重启后端；scheduler 会自动注册带 `schedule` 的 skill
3. 飞书远程：含 `fs` / `exec` / docgen 的 skill 会被 `skill_usable_via_remote` 拒绝

## 添加 MCP Server

见设置 → 连接器，或编辑 `~/.my-cowork/mcp.json`。

## 办公助手与 OfficeCLI

- Hub → **智能体 → 办公助手**：按场景分类（演示文稿 / 文档 / 表格 / 法务 / 通用）；选助手会预加载对应 skill 并注入 `rules`。
- 卡片上的推荐提问会新建会话并填入输入框（`my-cowork:composer-fill`）。
- **垂直场景（相对通用 PPT/Word/Excel）**
  - 路演 PPT → `officecli-pitch-deck`
  - Word 表单 → `officecli-word-form`
  - 数据仪表盘 → `officecli-data-dashboard`
  - 财务建模 → `officecli-financial-model`
- **法务（内置整包，约 35MB）**
  - 技能目录：`resources/example-skills/china-legal-counsel/`（含 `knowledge-base/`）
  - Hub →「法务」→「中国法务顾问」；预加载 `china-legal-counsel`
  - 验收：`审查这份 NDA 草案的高风险条款（中国大陆法），并给出修改建议与依据`
  - 免责：AI 辅助，不构成法律意见；重大事项请执业律师/人工法务复核
  - 从上游刷新（维护用）：`npm run vendor:china-legal-skill`，再人工 review + commit
- **公文写作（内置）**
  - 技能目录：`resources/example-skills/official-document-writing/`（含 `references/`、`checklists/`）
  - Hub →「文档」→「公文写作助手」；预加载 `official-document-writing` + `officecli` / `officecli-docx`
  - 验收：`写一份关于增加项目经费的请示`；或 `按公文质量清单检查这份通知初稿`
  - 免责：辅助撰写与质检，不构成正式发文依据
  - 从上游刷新（维护用）：`npm run vendor:official-document-skill`，再人工 review + commit
- **手工验收 prompt 示例**
  - 仪表盘：`用一份虚构的月度销售表做经营仪表盘，含 KPI 与两张图`
  - 表单：`做一份员工入职信息采集表，字段含姓名/部门/入职日/紧急联系人`
  - 财务：`做一份 SaaS 三年 Base 情景模型，含 Assumptions 与 P&L`
  - 公文：`写一份部门周例会通知，主送各处室`
- **本期未做**：Morph PPT、学术论文助手、自定义助手 CRUD、会话中途换助手。
- **推荐：捆绑二进制**。开发机执行一次 `npm run fetch:officecli`（写入 `resources/bin/officecli`）；正式包由 `build-electron.sh` / CI 自动拉取并打进 `extraResources/bin/`。
- Electron 启动时设置 `MY_COWORK_OFFICECLI` 指向捆绑路径，Agent / 预览优先用内置二进制，**无需使用中联网安装**。
- 若未捆绑且本机也没有：预览会走官方 install 脚本兜底；也可用 `brew install officecli`。
- `document_agent` 优先用 `bash` 跑 `officecli`；内置 `*_gen` 仅作降级。
- `officecli` 命令首次确认后，同任务内后续 officecli 调用自动放行。

1. 复制 `config.template.toml` → `config.toml`
2. 增加 `[mcp.servers.<name>]` 的 `command` / `args`
3. 重启后端；工具以 `mcp.<name>.<tool>` 注册

## 认知内核

运行时只有一套内核：自管 Act 循环 + 子任务交卷后质量分析 + 会话线程。Workforce 走 coordinator → workers → synthesize；单 Agent 走同一套 Act 循环，不再使用 LangChain `create_agent`。

质量门槛（金标集，`backend/eval/`）：

```bash
cd backend && PYTHONPATH=. uv run python eval/runner.py
```

金标集覆盖纯问答 / 需检索 / 追问改稿 / 公文 / PPT / 调研交付 / 拒答边界。
对照标准：**单 Agent 终稿 = Act 循环最后一条用户向回复**（二次合成只抢救 dump / 空文 / 计划）；**Workforce 终稿含工人 findings / `<summary>`**。调研须有多次检索 + 打开原文 + 终稿引用 fetch URL；办公文件须为真且过校验。不把二次合成当质量来源。不允许空壳 / snippet 作文 / 幻觉链接 / 计划当答案。
有真实模型时设 `MY_COWORK_EVAL_LIVE=1` 可再跑一遍；调研题轨迹应含 ≥2 次不同 query 的 `web_search` 与 ≥2 次 `web_fetch`。

## 内置检索

- 工具：`web_search` / `web_fetch` / `browser_*`
- Provider：博查 / Brave / Tavily / Exa / SearXNG，兜底 DuckDuckGo（免 Key）
- 配置：`config.toml` 的 `[tools.web]`，或设置页「检索」，Key 进系统钥匙串
- 环境变量：`BOCHA_API_KEY` / `BRAVE_API_KEY` / `TAVILY_API_KEY` / `EXA_API_KEY` / `SEARXNG_URL` / `MY_COWORK_SEARCH_PROVIDER`

## 记忆 / 预算（M5）

- 长期记忆：`~/.my-cowork/memory.db`（sqlite-vec）。**仅当配置 `MY_COWORK_EMBED_MODEL` 时语义召回**；未配置则关闭自动召回，不再用 64 维 hash 假装语义检索。用户明示「记住 …」仍会写入。
- 上下文压缩：消息 token > 120k 时调用廉价模型 `model_picker("compress")`（无 Key 则离线摘要）
- 单任务硬截断：默认 200k token（`MY_COWORK_MAX_TOKENS`）；超限发 `budget.exhausted`
- 日成本告警：`MY_COWORK_DAILY_USD`（默认 10），超限发 `metrics.daily_exceeded`
