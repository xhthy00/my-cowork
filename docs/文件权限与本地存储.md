# 文件权限、技能与密钥存储

本页说明文件访问权限、技能位置与密钥迁移行为。

## 文件访问

默认不授权整个用户主目录或桌面/文档/下载。文件工具可访问用户绑定的工作目录和当前任务生成目录；额外目录在“设置 → 隐私 / 白名单”添加。该设置通过 `/api/admin/whitelist` 保存到后端数据目录的 `directory-permissions.json`，只有服务器保存成功才更新界面状态。

绑定目录和手动添加目录是不同授权来源。解绑会撤回仅由该绑定授予的权限，其他仍有效绑定或手动授权不受影响。每次文件工具操作都检查当前绑定，运行过的任务不会把源目录永久留在白名单中。当前任务内部输出权限不会变成其他任务的全局权限。

应用技能资源目录另有内部只读访问，供读取技能正文、参考文件和脚本；不会因此获得改写技能或访问相邻用户文件的权限。

白名单不等于操作系统隔离：shell 工具检查工作目录、命令过滤及确认，但无法仅凭工作目录限制命令内部的全部文件访问。远程渠道和自动任务另有各自的授权路径，见[定时任务实现](定时任务实现.md)。

## 技能保存与迁移

- 用户技能默认放在 `~/.my-cowork/skills`；设置 `MY_COWORK_DATA_DIR` 时放在该数据目录的 `skills` 下，`MY_COWORK_SKILLS_ROOT` 可明确指定技能目录。
- 内置技能继续从 `resources/example-skills` 读取；不因指定用户目录而隐藏内置内容。
- 启动时复制旧安装目录或旧用户位置的技能，校验内容后使用新副本，旧副本保留。冲突不覆盖，在技能页给出提示。失败时保留旧位置供读取，下次启动重试。
- 成功迁移记录在用户技能目录的 `.migration-v1.json`。此后不再扫描保留的旧副本，避免用户删除技能后再次出现。调整自定义目录前应连同迁移记录和用户技能一起备份。
- 导入和市场安装共用目标校验：技能 id/name 必须是安全的单个目录名称；路径越界、特殊 Windows 路径及指向目录外的链接被拒绝。更新技能先复制完整内容，再替换已有安装。
- 更新及回滚都失败时，保留备份并在错误中给出恢复位置。旧技能配置损坏时提示该项迁移失败，继续处理其他技能，原文件保留。
- 安装包只带仓库 `skills/_templates` 和 README，不收集开发者的用户技能。

## 密钥保存与迁移

Electron `safeStorage` 使用系统提供的加密能力，密文保存到应用 userData 下的 `credentials.enc`。Windows 使用 DPAPI；它不能防御以相同系统用户身份运行的其他应用。Linux 的 `basic_text` 后备不视为安全可用。机制说明见 [Electron safeStorage 文档](https://www.electronjs.org/docs/latest/api/safe-storage)。项目当前 Electron 35 使用其已有同步 API。

系统加密不可用或密文无法解密时，明确返回错误；不新建明文后备，也不自动切换为“只在本次会话保留”。原加密文件不能被当作空配置覆盖。

旧 `credentials.json` 会在访问凭据时自动迁移：合并已有安全存储内容，写入密文并读回核对，成功后才移除旧明文；失败时保留旧文件供处理后重试。已使用 keytar 的旧凭据仍可读取并迁移到新存储，不将密钥写入日志。应使用应用设置修改凭据，不直接编辑密文文件。
