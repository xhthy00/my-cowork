# 模型兼容性检查（2026-10-14）

已检查项目的云端预设、原生 GLM 接口、OpenRouter、本地 OpenAI 兼容接口和备用模型链。发现的问题已修复，兼容逻辑集中在共享 `model_integrations` 和 harness 的公开 middleware，不新增独立 Python 环境，也不修改厂商 SDK 的私有实现。

这里的“通过”指使用实际 SDK 和官方 Deep Agents 图，对模拟 HTTP JSON/SSE 响应进行协议回归。没有使用真实厂商凭据调用付费模型，因此不表示每个线上模型、账号权限和本地模型模板都已验收。

## 检查结果与执行策略

| 接口 | 发现的风险 | 当前处理 |
| --- | --- | --- |
| OpenAI | 推理参数与普通模型不同；备用链绑定工具后无法执行 | 只给原生推理型号设置 reasoning effort；规划使用指定 write_todos；备用链通过公开 invoke/ainvoke 执行真实绑定模型 |
| Anthropic | 新版不接受旧手动思考预算；部分新版拒绝强制工具；自定义地址被忽略；默认 Sonnet 4 已退役 | 按版本选择 manual/adaptive；新代际使用 auto；完整保留思考签名；透传地址；新增配置默认 Sonnet 5.5 |
| DeepSeek | 思考模式拒绝指定工具；工具循环缺少历史 reasoning_content | 首次规划副本关闭思考，后续恢复；补齐原生历史字段 |
| Kimi / Moonshot | 思考模式拒绝指定工具；enable_thinking 并非其原生参数 | 规划使用 required 且只暴露 write_todos；K2.5/2.6 使用 thinking.type；思考专用型号不强制关闭；回传推理历史 |
| GLM / Z.AI | 接口声明只支持 auto；新思考型号不能关闭；错误套用模板参数 | 使用 auto 和官方图 hook 校验规划；支持切换的型号使用 thinking.type；GLM-5.3 不发送 disabled；保留推理历史 |
| Qwen / DashScope | 思考模式拒绝 required/指定工具；部分型号只支持流式；关闭模式未明确传参 | 使用 auto；可切换型号明确传 enable_thinking；思考/旧专用型号启用 SDK streaming，包含内部摘要调用 |
| MiniMax | 思考专用型号不能关闭；不同版本推理字段格式不同 | 使用保守的 auto 策略，不推断关闭参数；保留默认内容及已返回的 reasoning_content |
| OpenRouter | 通用 OpenAI SDK 无法完整回传加密 reasoning_details；平台下游能力不同 | 改用官方 langchain-openrouter，保留签名；规划使用 auto；不把直连厂商参数发送给网关 |
| Ollama / LM Studio / vLLM / 自定义 | 服务和模型工具能力不同；根据型号名猜参数可能导致 400 | 默认 auto，不根据模型名注入厂商参数；未收到有效规划前不执行业务工具或显示正文 |

Kimi 的 required 策略依据[工具选择说明](https://platform.kimi.ai/docs/guide/use-tool-choice)。GLM 的 auto 和思考策略依据[接口定义](https://docs.z.ai/api-reference/llm/chat-completion)及[思考模式说明](https://docs.z.ai/guides/capabilities/thinking-mode)。Qwen 的限制依据[工具调用说明](https://docs.modelstudio.console.alibabacloud.com/en/model-studio/qwen-function-calling)及[深度思考说明](https://www.alibabacloud.com/help/en/model-studio/deep-thinking)。

Claude 依据[思考模式说明](https://platform.claude.com/docs/en/build-with-claude/extended-thinking)、[Sonnet 5.5 迁移指南](https://platform.claude.com/docs/en/models/sonnet-5-5/migration-guide)及[退役列表](https://platform.claude.com/docs/en/about-claude/model-deprecations)。新默认值不改写已保存的配置；已有 `claude-sonnet-4-20250514` 直连配置需要重新选择可用型号。旧型号仍保留协议测试，用来覆盖手动思考兼容逻辑。

DeepSeek 依据[接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)及[多轮思考要求](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)。MiniMax 依据[OpenAI 兼容接口说明](https://platform.minimax.io/docs/api-reference/text-openai-api)。OpenRouter 使用[官方 LangChain SDK](https://reference.langchain.com/python/langchain-openrouter/chat_models/ChatOpenRouter)。Ollama 的[兼容文档](https://docs.ollama.com/api/openai-compatibility)列出 tool_choice，但具体模型是否能可靠调用工具仍需验证。

## 规划、历史与备用链

初次规划只暴露官方 write_todos 工具。支持指定工具的接口在模型副本上处理思考冲突；Kimi 使用 required；其他接口使用 auto。auto/required 模型若输出正文或错误工具，官方 after_model hook 将其退回模型节点，最多三次。没有有效步骤之前，正文流不发布，也不执行业务工具。后续恢复完整工具集合及原模型配置。

原生 DeepSeek、Kimi、GLM、Qwen 和 MiniMax 的 reasoning_content 响应采用官方 langchain-deepseek 的同格式 JSON/SSE 解析器，传入各自真实 endpoint。需要回传 reasoning_content 的原生接口通过公开消息转换及 extra_body 补齐历史；Qwen 不额外回传该字段。OpenRouter 的 reasoning_details 由其专用 SDK 处理；Anthropic 的 thinking/signature 块由其专用 SDK 原样保存。

备用链此前对绑定对象调用私有生成方法，会在真实 SDK 中失败。现在采用公开调用接口，并透传子调用 callbacks：实际请求计一次步数和用量，路由包装器不重复计数。明确的 400/401/403/404/422 不触发备用，避免把参数或鉴权错误误判成可重试；瞬时 408/429/5xx 可切换备用。

切换到不同 provider 协议时不继承主模型的 base_url/options。环境变量备用配置仍共用 MY_COWORK_API_KEY，因此不同厂商的独立凭据并不会凭空获得；配置备用时必须确保该凭据和 endpoint 可用于目标模型。

## 验证与剩余边界

- 专项回归：84 项通过。其中完整 SDK/图矩阵 44 项，覆盖 JSON/SSE、规划工具限制、业务工具调用、思考历史/加密签名、首次错误正文/工具拦截、规划失败上限、备用链及用量计数。
- 后端完整测试：713 项通过；4 条依赖边界契约通过。
- 前端完整测试：462 项通过；TypeScript 和 Vite 生产构建通过。
- 原生 DeepSeek 的独立协议回归继续通过；旧 Claude 协议用例产生的退役警告符合预期。
- macOS arm64 冻结构建通过，实际二进制的 harness 私有鉴权/SQLite readiness 和后端→同可执行文件 harness 联合启动均通过。Windows spec 已同步，未进行 Windows 真机验收。

共享锁加入 langchain-openrouter 0.2.9；其依赖约束使 Pydantic 求解到 2.12.5，已通过完整后端回归。macOS/Windows 打包 spec 均收集新增 SDK。

当前保存界面的 ping/模型列表验证主要检查连通性，不是完整 Agent 能力验收。真实账号仍可能遇到模型退役、无权限、限流或厂商变更；本地模型还可能缺少工具模板、上下文窗口不足或无法遵守规划指令。任意第三方转发站和本地模型不承诺通用兼容。本次不自动迁移用户的既有模型、不消耗厂商余额进行线上测试。

上下文窗口需要单独验收。SDK 不认识的型号没有可靠的 profile，官方 Deep Agents 当前会采用固定 token 数触发摘要；这一阈值可能超过小窗口本地模型的容量。本次矩阵验证多轮协议，没有验证长上下文压力。累计任务 token 默认不限量也不代表单次模型输入可无限增长。

MiniMax 官方端点现补齐已公布型号的窗口 profile：M3、M3.1-Flash-Preview 为 1,000,000；M2/M2.1/M2.5/M2.7 及对应 highspeed 型号为 204,800，依据[官方接口型号表](https://platform.minimax.io/docs/api-reference/text-openai-api)。SDK 有有效 profile 时优先采用 SDK；补齐值同时用于显示和官方摘要比例阈值。新增回归覆盖元数据接口、官方摘要配置、SDK 更新优先、自定义端点隔离以及 M3 的 JSON/SSE 实际执行协议；未进行真实付费模型或长上下文压力调用。

兼容性测试包含在现有完整 pytest 和候选依赖升级流水线中。以后 Deep Agents 或 SDK 的升级必须继续通过这些检查；协议变更仍可能需要小范围适配，不能承诺第三方接口永远无需维护。
