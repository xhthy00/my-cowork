# MyCowork 知识库集成方案 v0.1

> 定位：MyCowork **不重建知识库**，而是作为"**统一知识库客户端**"，通过 MCP（首选）+ REST（兜底）接入市面上成熟的 RAG / 知识库产品（腾讯 ima、RAGFlow、FastGPT、Dify、Coze 知识库等）。  
> 取代：早期草稿"自建 KB 层（chunking + sqlite-vec 多表）"——发现 MyCowork 已有完整 MCP 客户端（`tools/mcp/manager.py`）+ `mcp.json` 配置 + McpConnectorsPanel UI，无需再造轮子。  
> 写作依据：`tools/mcp/manager.py` 实测（stdio/HTTP/SSE 三协议）、`server/routes/mcp.py`、`renderer/.../McpConnectorsPanel.tsx`、`config.template.toml`、`落地方案.md` v1.4 §1.1；目标产品 README/官网整理。

---

## 1. 方向修正：为什么是"集成"而非"自建"

### 1.1 早前方向错在哪

最初把知识库理解为"个人文档 + 向量索引"，于是设计了：

- 新建 `app/knowledge/` 包（chunking + embedding + sqlite-vec 多表 + watcher + REST + UI）
- 共 ~2560 行代码（主体 1100 行）
- 实际上**和 RAGFlow / FastGPT / Dify 知识库功能 80% 重合**

### 1.2 修正后的判断

知识库是个**重运营的产品形态**（文档解析、OCR、表格识别、图谱、跨编码器 reranker、权限、协作）——专业的事交给专业的产品做。MyCowork 的角色是**整合者**：

| 角色 | 谁来做 | 例子 |
|---|---|---|
| **数据/解析/索引** | 专业 KB 产品 | RAGFlow、FastGPT、Dify、ima、Coze 知识库、Cherry Studio 内置库 |
| **检索协议统一** | MyCowork（薄层） | MCP / REST 适配器、引用规范化 |
| **Agent 调用** | MyCowork | 单个 `kb_query` 工具，统一给 LangGraph Worker |
| **结果后处理** | MyCowork | 引用拼接、去重、置信度提示、来源徽章 |

MyCowork 已在 `tools/mcp/manager.py` 实现了 stdio/HTTP/SSE 三协议 MCP 客户端 + ToolRegistry 注册（`mcp.<server>.<tool>` 命名），这就是"薄层"的天然地基。

## 2. 目标产品能力地图

按"MCP 成熟度 + 用户量"排序，MyCowork 重点接入以下四类：

| 产品 | 类型 | 接入方式 | 核心能力 | 适配工作量 |
|---|---|---|---|---|
| **腾讯 ima**（https://ima.qq.com） | 云端 SaaS + 个人库 | MCP server（SSE） | 个人上传文件 + 共享知识库 + 智能问答 | **小**：接 MCP 即可，预计 1-2 天 |
| **RAGFlow**（infiniflow/ragflow） | 开源自托管 | **REST API**（同时也有 MCP） | 数据集/文档/块、OCR、表格、图谱、Agent | **中**：REST 适配器，预计 3 天 |
| **FastGPT**（labring/FastGPT） | 国内开源 SaaS/自托管 | REST API + MCP | 知识库 + 应用 + 工作流 | **中**：REST 适配器，3 天 |
| **Dify** | SaaS + 自托管 | REST API + MCP | 知识库 + Agent + 工作流 | **小**：MCP 成熟，1 天 |
| **Coze 知识库**（字节） | SaaS | MCP server | 个人/团队知识库 | **小**：MCP，1 天 |
| **Cherry Studio** | 桌面客户端 | 内置 MCP / 直连 | 本地 + 远端 KB 聚合 | **极小**：直接 import mcp.json |
| **MaxKB** | 开源企业 KB | REST API | 企业文档问答 | **中**：REST 适配器，3 天 |
| **AnythingLLM** | 桌面 | MCP server | 多源 + 多向量后端 | **小**：MCP，1 天 |

**结论**：MVP 覆盖 **ima + RAGFlow**（最具代表性：闭源 + 开源 + 中文场景）；FastGPT / Dify 留给 M8.x 增量补。

## 4. 设计细节

### 4.1 配置：`~/.my-cowork/kb-config.json`

```jsonc
{
  "version": 1,
  "sources": [
    {
      "id": "ima-personal",
      "kind": "mcp",                    // mcp | rest | local
      "mcp_server": "ima",              // 对应 mcp.json 里的服务器名
      "tool_name": "ima_search",        // 该 MCP server 提供的检索工具
      "description": "腾讯 ima 个人知识库",
      "default_top_k": 5,
      "enabled": true
    },
    {
      "id": "ragflow-projects",
      "kind": "rest",
      "base_url": "http://localhost:9380/api/v1",
      "api_key_ref": "ragflow_key",     // 引用 keychain / .env 别名
      "dataset_ids": ["ds_xxx", "ds_yyy"],
      "default_top_k": 5,
      "enabled": true
    },
    {
      "id": "local-files",
      "kind": "local",
      "roots": ["~/Documents/AIS"],     // PathGuard 白名单内的目录
      "default_top_k": 3,
      "enabled": true
    }
  ]
}
```

- `mcp` 类型源：MyCowork 自动从已加载的 MCP server 中按 `tool_name` 找工具，不存在则 `sources/test` 返回 404 + 提示
- `rest` 类型源：MyCowork 通过对应的 connector 类（见 §4.3）调用
- `local` 类型源：MVP 不做（v0.2 留接口），先指向已有的 `fs_read`

### 4.2 核心门面工具：`kb_query`

```python
# backend/app/tools/builtin/kb_query.py

@tool
def kb_list_sources() -> str:
    """List configured knowledge base sources.

    Returns JSON array of {id, kind, description, enabled, default_top_k}.
    Call before kb_query when unsure which source to query.
    """
    ...

@tool
def kb_search(query: str, source: str | None = None, top_k: int = 5) -> str:
    """Search the user's configured knowledge bases.

    Args:
      query: natural-language question.
      source: optional source id from kb_list_sources(); omit to query all.
      top_k: how many chunks per source (default 5).

    Returns JSON array of citations:
      [{source_id, title, breadcrumb, snippet, score, url?, doc_id?}]

    Cite as [kb:<source_id>:<doc_id>] when using a snippet in your answer.
    """
    ...
```

**路由策略**：

| `source` 参数 | 行为 |
|---|---|
| 指定 `source='ima-personal'` | 单源调用该后端，返回 ≤top_k 条 |
| 未指定 | **并行 fanout** 所有 enabled 源，收集结果，按 score 排序后取 top_k 总数 |
| 源不可达 | 单源失败 → 降级提示 + 返回其他源；全部失败 → 返回 `[KB_UNAVAILABLE]` 提示 |
| `top_k` > 源支持的 max | 截断到 max，不报错 |

### 4.3 REST 连接器（RAGFlow 为例）

```python
# backend/app/tools/builtin/kb_connectors/ragflow.py

class RAGFlowConnector:
    """RAGFlow v0.18+ REST API 适配器。
    端点: POST /api/v1/retrieval
    鉴权: Authorization: Bearer <api_key>
    """

    name = "ragflow"

    def __init__(self, base_url: str, api_key: str, dataset_ids: list[str]):
        self.base_url = base_url.rstrip("/")
        self.api_key = api_key
        self.dataset_ids = dataset_ids

    def health(self) -> bool:
        ...   # GET /datasets

    def search(self, query: str, top_k: int = 5) -> list[Citation]:
        payload = {
            "question": query,
            "dataset_ids": self.dataset_ids,
            "top_k": top_k,
            "similarity_threshold": 0.2,
        }
        with httpx.Client(timeout=20.0) as c:
            r = c.post(
                f"{self.base_url}/retrieval",
                headers={"Authorization": f"Bearer {self.api_key}"},
                json=payload,
            )
            r.raise_for_status()
            data = r.json()
        return [
            Citation(
                source_id="ragflow",
                doc_id=ch.get("document_id", ""),
                doc_name=ch.get("document_name", ""),
                snippet=ch.get("content", ""),
                score=float(ch.get("similarity", 0.0)),
                breadcrumb=ch.get("positions", ""),
                url=ch.get("url"),
            )
            for ch in data.get("data", {}).get("chunks", [])
        ]
```

ima / FastGPT / Dify 各写一个类似 connector（共 ~120 行/个）。所有 connector 实现统一接口 `KBConnector.health() / search()`。

### 4.4 MCP 类型源的处理（零代码）

MCP 后端的工具**已经通过 `tools/mcp/manager.py` 自动注册到 ToolRegistry**，命名为 `mcp.<server>.<tool>`。`kb_query` 只需要：

1. 在 `kb-config.json` 里指明 `kind="mcp"` + `mcp_server="ima"` + `tool_name="ima_search"`
2. `kb_query` 内部 `registry.get("mcp.ima.ima_search")` 拿到 tool
3. 用 LangChain `BaseTool.invoke({"query": ..., "top_k": ...})` 调用
4. 把返回结构标准化成 Citation 列表

**这是零代码路径**——只要产品提供 MCP server，MyCowork 接它只要在 kb-config.json 里加一段配置。

### 4.5 引用规范化

所有后端返回的 chunks 统一映射成：

```python
@dataclass
class Citation:
    source_id: str      # kb-config 里的源 id
    doc_id: str         # 后端返回的文档/块 id
    doc_name: str       # 人读标题
    snippet: str        # ≤ 600 字摘要
    score: float        # 0~1 相似度
    breadcrumb: str     # "page 3 / §1.2 / # 第三章"
    url: str | None     # 后端可能给的预览链接
    raw: dict           # 原始 payload，便于 UI 调试
```

Agent 在答案里写 `[kb:<source_id>:<doc_id>]` 作为引用锚点；UI 渲染时点击可跳转到对应源（本地文件 `fs://` 协议 / 远程 URL）。

### 4.6 System Prompt 调整

在 `single_agent.md` 加一段：

```markdown
<knowledge_base>
- `kb_list_sources()` returns all configured knowledge bases the user added
  (腾讯 ima, RAGFlow, FastGPT, Dify, etc.). Call it when unsure which source
  covers the topic.
- `kb_search(query, source=None, top_k=5)` queries sources and returns
  citations as JSON. Each citation has [kb:<source>:<doc_id>] format.
- When you use a snippet in your answer, include the citation verbatim:
  `[kb:ragflow-projects:doc_abc]`.
- KB is independent of long-term memory (`remember ...`) and short-term
  notes (`create_note`). KB is for the user's external corpora, not facts
  about them.
- Prefer kb_search over fs_read when the user asks about documents in
  their added knowledge bases (e.g., "看看我之前上传的合同").
- If kb_search returns [KB_UNAVAILABLE], fall back to fs_read on the
  user's working directory and warn the user the KB was unreachable.
</knowledge_base>
```

## 6. 安全

- **所有 REST 源**的 `api_key` **不落盘明文**：写入 keychain（已有 `keytar` 跨平台封装），kb-config.json 只存 `api_key_ref` 别名
- **所有 MCP server**沿用现有 `mcp.json` 沙箱：stdio 进程隔离；HTTP/SSE 走 `assert_allowed_url`（已有）
- **KB 工具不绕过确认门**：当 Agent 想 `kb_search` 时，若 `--require-approval` 配置开启，走现有 `ConfirmHub`
- **不向 Agent 暴露 kb-config.json 内容**：仅返回 `kb_list_sources()` 的 4 个字段，隐藏 base_url / api_key
- **检索结果过滤**：snippet 截断 600 字，避免 LLM 上下文爆炸

## 10. 风险与回退

| 风险 | 缓解 | 回退 |
|---|---|---|
| ima API 未公开或鉴权复杂 | 优先 MCP 路径（ima 已承诺 MCP）；REST 只在 MCP 不通时启用 | 仅 MCP，REST 标 P1 |
| RAGFlow REST API 字段变动 | 写适配器时严格按官方 OpenAPI/SDK；测试用录制的真实响应 | 切到 RAGFlow MCP（同样支持） |
| MCP server 加载慢影响 kb_query 响应 | 已有 `set_enabled_mcp` ContextVar；kb_query 仅 invoke 已缓存 tool | UI 加"加载中"提示 |
| kb-config.json 误配置（指向不存在 server） | `kb_search` 返回 `[KB_UNAVAILABLE: <source>]` 而非崩溃 | UI 标红 + 一键修复 |
| keychain 在 headless 环境不可用 | 检测 `keytar` 异常时 fallback 到 `MY_COWORK_KB_KEY_*` 环境变量 | 文档明示 + UI 警告 |
| Agent 误用 kb_search 调用云端敏感 API | `require_approval = true` 时走 ConfirmHub | 默认 false；用户自决 |
