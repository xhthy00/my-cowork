# MyCowork 行业应用插件开发指南（v1）

本文说明如何开发、打包和安装能在 MyCowork「行业工作台」中运行的行业应用。当前插件类型为 Python 后端加静态 Web 页面，适合任务管理、轻量 ERP 扩展、行业表单和本地业务台账等应用。

本文对应当前仓库中的实现。开发前可先运行 [任务管理样例](../examples/taskboard/README.md)，协议细节以 [包校验器](../backend/app/industry_apps/package.py)、[加载器](../backend/app/industry_apps/loader.py) 和 [工作台页面](../renderer/src/components/hub/IndustryWorkbench.tsx) 为准。后续演进方向见 [实现方案](./行业应用包与工作台实现方案.md)。

## 1. 运行模型

一个插件 ZIP 包含：

- 根目录的清单和校验表；
- 一个具有独立名称的 Python 包，提供 FastAPI 路由；
- 一个已构建的静态 Web 页面，显示在工作台内。

安装时，宿主检查 ZIP 路径、文件大小、清单和每个文件的 SHA-256。安装完成后需要重启后端。后端启动时导入插件的 Python 入口，将其路由挂到 /api/apps/{应用 ID}；页面则通过 mycowork-app:// 协议加载到 iframe 中。页面调用后端时，使用工作台提供的 postMessage 桥接。

**信任边界：** Python 代码在 MyCowork 现有后端进程内执行，可访问该进程的 Python 环境和操作系统资源。当前版本没有进程级隔离。请只安装来源可信、经过审查的应用。页面有独立来源、资源访问限制和受控桥接，但这不能隔离后端 Python 代码。

## 2. 开发环境与目录

当前宿主使用 Python 3.11 或 3.12。前端可以使用任意框架或原生 HTML、CSS、JavaScript，交付物必须是无需开发服务器的静态文件。插件安装器不会执行 pip、npm，也不会为每个插件创建单独的 Python 虚拟环境。

推荐目录如下。以下示例的应用 ID 是 cn.example.taskboard，因此 Python 根包名称是 mcapp_cn_example_taskboard。

~~~text
taskboard/
├── mycowork-app.yaml
├── backend/
│   └── mcapp_cn_example_taskboard/
│       ├── __init__.py
│       ├── plugin.py
│       └── storage.py              # 可选
└── frontend/
    └── dist/
        ├── index.html
        ├── app.js
        ├── style.css
        └── assets/                 # 可选；图片、字体等本地资源
~~~

打包脚本会在 ZIP 根目录自动生成 checksums.sha256。不要手工维护该文件。测试、构建缓存、node_modules、开发文档等建议放在插件源码目录之外，避免被打进 ZIP；当前打包脚本会收集源码目录下除 __pycache__、.pyc 和 checksums.sha256 以外的普通文件。

### 必需路径

| 路径 | 作用 |
| --- | --- |
| mycowork-app.yaml | 插件清单，必须位于 ZIP 根目录 |
| backend/mcapp_<ID 中点号改为下划线>/__init__.py | Python 包标识 |
| frontend/dist/index.html | 页面入口 |
| checksums.sha256 | 每个其他 ZIP 文件的 SHA-256，由打包脚本生成 |

ZIP 不应在这些文件外再套一层目录。例如 ZIP 第一层应直接看到 mycowork-app.yaml，而不是 taskboard/mycowork-app.yaml。backend/ 下的文件必须全部位于该应用自己的 mcapp_ 根包之内。

## 3. 清单规范

可直接使用以下清单作为起点：

~~~yaml
schema_version: 1
id: cn.example.taskboard
name: 任务管理样例
version: 1.0.0
description: 带独立页面与 SQLite 数据的本地任务管理应用
min_host_version: 0.0.9
sdk_version: 1
kind: python-web
platforms: [darwin-arm64, darwin-x64, win-x64]
backend:
  entry: mcapp_cn_example_taskboard.plugin:register
  requires_python: ">=3.11,<3.13"
ui:
  entry: frontend/dist/index.html
  route_mode: hash
  bridge_version: 1
  min_width: 640
data:
  scope: workspace
capabilities:
  host_api: []
  network_domains: []
skills: []
~~~

| 字段 | 当前 v1 规则 |
| --- | --- |
| schema_version | 必须为 1 |
| id | 必填；反向域名形式的小写字母和数字，以点号分段，例如 cn.example.erp；每段首字符必须是小写字母 |
| name | 必填，1～80 个字符 |
| version | 必填，数字 MAJOR.MINOR.PATCH，例如 1.2.0；不接受预发布后缀 |
| description | 可选，最多 500 个字符 |
| min_host_version | 可选，数字 MAJOR.MINOR.PATCH；宿主版本低于此值时拒绝安装 |
| sdk_version | 只能为 1 |
| kind | 只能为 python-web |
| platforms | 可选；空数组表示不限定；当前识别 darwin-arm64、darwin-x64、win-x64 |
| backend.entry | 必填，形式为 模块:函数；模块必须属于该应用的 mcapp_ 根包 |
| backend.requires_python | 只能写 ">=3.11,<3.13" |
| ui.entry | 只能写 frontend/dist/index.html |
| ui.route_mode | 只能为 hash |
| ui.bridge_version | 只能为 1 |
| ui.min_width | 可选，范围 320～1920；当前清单可保存此值，工作台暂未据此调整 iframe 宽度 |
| data.scope | 可选，workspace 或 global；当前推荐 workspace |
| data.migration_entry | 当前不可填写有效入口，数据迁移接口尚未开放 |
| capabilities.host_api | 当前必须为空数组 |
| capabilities.network_domains | 当前必须为空数组 |
| skills | 当前必须为空数组 |

清单会拒绝未知字段。建议只写需要的可选字段。ID 发布后应保持稳定：它同时决定 Python 包名、后端路由前缀、页面来源和数据目录。更新已有应用时保留 ID，递增 version。

平台选择只是安装时的兼容性声明。若代码仅使用宿主已有的纯 Python 依赖，通常可以省略 platforms；若代码确实依赖某个平台的行为，应显式列出已验证的平台。当前 ZIP 不支持附带 .so、.pyd、.dll、.dylib 或 .pyc。

## 4. Python 后端接口

入口函数签名为 register(context: AppContext) -> AppContribution。函数应创建并返回 FastAPI APIRouter，由宿主添加应用专属前缀。不要在路由里重复写 /api/apps/{应用 ID}。

~~~python
from fastapi import APIRouter
from pydantic import BaseModel, Field

from app.industry_apps.sdk import AppContext, AppContribution


class ItemInput(BaseModel):
    title: str = Field(min_length=1, max_length=200)


def register(context: AppContext) -> AppContribution:
    router = APIRouter()

    @router.get("/items")
    def list_items() -> dict:
        return {"items": []}

    @router.post("/items")
    def create_item(body: ItemInput) -> dict:
        return {"title": body.title}

    return AppContribution(router=router)
~~~

假设 ID 为 cn.example.taskboard，示例中的实际路径是 GET /api/apps/cn.example.taskboard/items 和 POST /api/apps/cn.example.taskboard/items。页面桥接请求只传相对应用路由的 /items。

AppContext 当前提供：

- app_id：清单中的应用 ID；
- data_root：应用数据根目录，供内部实现使用；
- workspace_data_dir(workspace_id)：创建并返回此应用在指定工作空间的数据目录。

workspace_id 不能为空，不能是 . 或 ..，也不能包含斜杠或反斜杠。当前 SDK 没有提供取得宿主当前工作空间 ID 的方法；插件应在自己的 API 请求中明确传入业务上选定的工作空间 ID。样例使用 local 作为默认值。不要把用户任意输入直接拼接到数据文件路径。

AppContribution 当前只接收 router 作为有效贡献。虽然类型中预留了 tools 和 jobs 字段，填入非空值会导致应用加载失败。注册 AI 工具和后台定时任务的 SDK 尚未开放。

### 编码约束

1. **入口要轻量。** register 在后端启动期间同步执行；避免在导入模块或注册路由时做大规模扫描、长时间迁移、网络请求或无限循环。
2. **路由要有清晰的数据模型。** 使用 Pydantic 校验输入长度、类型和必填字段；为不存在的资源返回适当的 HTTP 错误。
3. **依赖必须由宿主提供。** 当前安装过程不会解析 requirements.txt。优先使用 Python 标准库以及宿主已包含的 FastAPI、Pydantic 等依赖；新增依赖应先进入宿主的打包与兼容性流程。
4. **业务数据写入数据目录。** 安装目录按版本存储代码和页面；业务数据库、上传文件等应放在 context.workspace_data_dir(workspace_id) 下，避免更新或回退时丢失。
5. **数据库访问要可维护。** 轻量应用可以使用 sqlite3；SQL 参数使用占位符，连接及时关闭，写入显式提交。不同请求并发访问时须按数据库规则处理事务和锁。
6. **异常要可诊断。** 在接口层返回明确错误；不要把令牌、数据库密钥或用户隐私写入异常消息与日志。
7. **不要改动宿主全局状态。** 避免修改 sys.path、全局路由、宿主配置、其他插件目录或系统环境变量；加载器负责导入与路由挂载。

这些编码约束中，第 1、2、4～7 项是开发建议；ZIP 校验与入口返回值的限制由代码强制执行。由于插件与宿主共用进程，编码质量会直接影响整个后端的稳定性。

## 5. 页面与前后端桥接

页面入口固定为 frontend/dist/index.html。工作台会把它加载到 iframe 中，页面静态资源通过 mycowork-app://{应用 ID}/ 路径提供。HTML 中用相对地址引用脚本、样式和图片，例如 ./app.js、./style.css；前端路由使用 hash 模式。构建工具需要生成可直接从该入口加载的静态资源，避免依赖开发服务器或绝对站点根路径。

当前页面的资源策略允许同来源脚本、样式、字体和图片，以及 data: 图片；禁止内联脚本、内联样式和页面直接连接网络（包括 fetch 与 WebSocket）。请把脚本和样式输出为独立文件。页面也不能直接调用宿主 Electron API。业务请求必须走 postMessage 桥接，由工作台转给应用自己的后端路由。

桥接请求格式：

~~~js
{
  channel: "mycowork-app/v1",
  appId: "cn.example.taskboard",
  bridgeToken: "...",          // 从 index.html?bridge=... 读取
  id: "request-1",             // 当前页面内唯一的请求 ID
  type: "request",
  operation: "app.request",
  method: "GET",
  path: "/items",
  body: undefined
}
~~~

桥接响应包含相同的 channel、appId、bridgeToken、id，type 为 response；成功时 ok: true 且 data 为后端返回的 JSON，失败时 ok: false 且 error 为错误文本。允许的方法为 GET、POST、PATCH、PUT、DELETE。path 以 / 开头，可以包含查询参数，但不能包含路径穿越、反斜杠、片段标记或编码后的斜杠。请求最终只会到本应用的 /api/apps/{应用 ID} 前缀。

一个最小可用的页面调用封装：

~~~js
const channel = "mycowork-app/v1";
const appId = "cn.example.taskboard";
const bridgeToken = new URLSearchParams(location.search).get("bridge");
const pending = new Map();
let nextId = 0;

window.addEventListener("message", (event) => {
  if (event.source !== window.parent) return;
  const message = event.data;
  if (
    !message ||
    message.channel !== channel ||
    message.appId !== appId ||
    message.bridgeToken !== bridgeToken ||
    message.type !== "response"
  ) return;
  const item = pending.get(message.id);
  if (!item) return;
  pending.delete(message.id);
  clearTimeout(item.timer);
  if (message.ok) item.resolve(message.data);
  else item.reject(new Error(message.error || "请求失败"));
});

function request(method, path, body) {
  if (!bridgeToken) {
    return Promise.reject(new Error("请从 MyCowork 工作台打开此应用"));
  }
  return new Promise((resolve, reject) => {
    const id = String(++nextId);
    const timer = setTimeout(() => {
      pending.delete(id);
      reject(new Error("宿主响应超时"));
    }, 15000);
    pending.set(id, { resolve, reject, timer });
    window.parent.postMessage({
      channel, appId, bridgeToken, id,
      type: "request", operation: "app.request",
      method, path, body
    }, "*");
  });
}

request("GET", "/items").then(console.log);
~~~

这里使用 * 作为发送给父窗口的目标来源，是因为宿主页面在不同运行方式下可能有不同来源。工作台会检查发件 iframe、来源、应用 ID 和 bridgeToken；插件页面收到响应时也应检查 event.source、应用 ID、令牌和请求 ID。令牌只用于这条页面消息通道，不代表插件获得了任意宿主 API 权限。

界面开发建议：

- 给加载、空列表、失败和提交中状态提供清晰反馈；
- 用户内容用 textContent 或安全的框架文本插值渲染，避免直接拼进 innerHTML；
- 页面应适应工作台容器宽度和约 600 像素起的高度；
- 将脚本、样式、图片和字体一起打包，不引用 CDN；使用 Vite 等构建工具时配置相对资源基路径（例如 ./）；
- 完成构建后从 frontend/dist/index.html 检查相对资源路径。

## 6. 数据、升级和版本

默认安装根目录为 MyCowork 数据目录下的 industry-apps；通常位于 ~/.my-cowork/industry-apps。开发或测试时可用 MY_COWORK_INDUSTRY_APPS_ROOT 覆盖。主要路径：

~~~text
industry-apps/
├── registry.json
├── packages/
│   └── cn.example.taskboard/
│       ├── 1.0.0/
│       └── 1.1.0/
└── data/
    └── cn.example.taskboard/
        └── local/
            └── tasks.db
~~~

注册表记录当前版本、上一版本、启用状态及加载状态。安装新版本后状态为 pending_restart，重启后端并成功加载才会变为 ready；入口异常会显示 load_failed 和错误。应用可停用、重新启用或手动回退到上一版本，这些操作也需要重启后端才能作用于已经加载的 Python 代码。当前没有自动回退或卸载流程。

更新代码与页面时递增版本并重新打包。数据目录不随代码版本切换，因此新旧版本必须能处理同一份业务数据。当前没有受宿主管理的数据迁移入口：如需改变 SQLite 表结构，应在插件自己的业务代码中谨慎处理兼容，并先备份测试数据。data.scope 虽然接受 global，但当前 SDK 只提供 workspace_data_dir 便捷方法；v1 应优先采用 workspace。

## 7. 打包、检查与安装

在仓库根目录执行：

~~~sh
python3 scripts/pack-industry-app.py examples/taskboard -o /tmp/taskboard-1.0.0.zip
~~~

将 examples/taskboard 换成自己的插件源码目录。输出 ZIP 必须放在源码目录之外。脚本使用固定文件顺序和时间戳，并生成 checksums.sha256；同样的文件内容可得到稳定的包。校验表用 UTF-8 编码，每行是 64 位小写十六进制 SHA-256、两个空格、ZIP 内相对文件路径，且必须恰好覆盖除校验表自身以外的所有文件。该校验表用于检测文件变化，不提供作者身份认证。

本地可用当前后端的校验器检查包：

~~~sh
PYTHONPATH=backend backend/.venv/bin/python -c 'from pathlib import Path; from app.industry_apps.package import inspect_zip; print(inspect_zip(Path("/tmp/taskboard-1.0.0.zip").read_bytes()).public())'
~~~

若本地虚拟环境路径不同，用运行 MyCowork 后端的 Python 3.11/3.12 环境执行，并确保已安装宿主依赖。

在 MyCowork 中打开「行业工作台」→「安装 ZIP」，选择包并查看名称、版本、ID 和文件数量。确认来源可信后安装，再点击「重启后端以应用变更」。状态变为 ready 后打开应用。安装前检查和实际安装会对同一个 ZIP 计算 SHA-256；如果文件在两步之间发生变化，安装会被拒绝。

### ZIP 限制

| 项目 | 上限或规则 |
| --- | --- |
| ZIP 文件大小 | 50 MiB |
| 解压后总大小 | 200 MiB |
| 单文件大小 | 50 MiB |
| 清单大小 | 64 KiB |
| ZIP 条目数量 | 1000 |
| 单文件解压比 | 不超过 1000 |
| 路径 | 相对路径；禁止上级跳转、重复路径、反斜杠、符号链接和设备文件 |
| 文件完整性 | checksums.sha256 必须覆盖除此文件之外的每一个文件 |
| 二进制内容 | 不接收原生扩展库及 Python 字节码 |

## 8. 开发验证清单

提交或分发 ZIP 前，至少完成以下检查：

1. 清单 ID、Python 根包目录名、backend.entry 和页面代码中的 appId 一致。
2. ZIP 根目录包含清单、校验表、Python 包初始化文件和 frontend/dist/index.html。
3. 用打包脚本生成 ZIP，并用 inspect_zip 成功检查。
4. 页面在工作台内打开，静态资源全部加载；列表读取、表单提交等关键操作通过桥接成功。
5. 应用使用自己的数据目录，关闭和重启后端后数据仍可读取。
6. 使用测试数据验证从旧版本升级，以及必要时手动回退。
7. 在准备声明的平台上实际运行并检查后端日志与工作台状态。

仓库中的 [任务管理样例](../examples/taskboard/) 提供完整的清单、SQLite 路由和页面桥接实现，可作为新插件的起点。复制时应同步修改 ID、Python 包名、清单入口和页面 appId。

## 9. 常见问题

**提示 invalid manifest：** 检查未知字段、版本格式、Python 范围、平台声明及尚未开放的 capabilities、skills、migration_entry。v1 不会忽略不支持的权限申请。

**提示 missing backend/.../__init__.py：** Python 根包名必须精确对应应用 ID，把点号替换为下划线并加 mcapp_ 前缀；ZIP 根目录也不能多套一层。

**安装后页面打不开：** 先确认状态为 ready；pending_restart 需要重启后端，load_failed 需要检查工作台显示的加载错误。检查前端构建产物的入口和相对资源路径。

**页面请求失败：** 确认页面从工作台打开，bridgeToken 存在，appId 一致；桥接 path 写 /items 这类应用内路径，不要自行添加 /api/apps/{应用 ID}。页面直接 fetch 后端会被资源策略阻止。

**依赖导入失败：** 当前 ZIP 安装不会 pip install。检查该依赖是否已由宿主后端提供；否则需要先完成宿主依赖与打包适配。

**更新后数据异常：** 数据目录由所有版本共用；检查数据库模式兼容性。当前回退只切换代码版本，不回滚业务数据。
