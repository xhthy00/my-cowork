# 前端设计

面向 Web 前端、H5、后台管理、官网、落地页、CMS 模板页面、品牌视觉、Banner、图标和社交媒体图片，提供从需求理解、设计思维、信息架构、视觉设计、交互状态、响应式布局到工程落地和浏览器验证的完整流程。

> 本模板已吸收 UI/UX Pro Max 规则，无外部依赖。设计优先级：无障碍 > 响应式 > 视觉层级 > 一致性 > 性能 > 交互反馈 > 排版 > 色彩 > 动效 > 间距（具体要求见后续步骤）。

## 输入要求

1. **页面/功能目标**（必填）：页面要解决什么用户问题或业务目标
2. **目标用户**（必填）：使用者角色、设备场景、操作频率
3. **内容素材**（可选）：文案、图片、品牌色、Logo、现有页面
4. **技术栈**（可选）：HTML/CSS/JS、Vue、React、Taro、CMS模板等
5. **设计约束**（可选）：品牌规范、兼容浏览器、SEO、性能、无障碍要求
6. **设计资产类型**（可选）：页面、组件库、品牌规范、Banner、图标、社媒图、数据图表

## 执行流程

### 第一步：需求与场景分析

- 明确页面核心目标和转化路径
- 识别用户角色、设备、访问入口和关键任务
- 明确交付类型：官网/后台/H5/表单/列表/详情/仪表盘/CMS模板/品牌规范/Banner/图标/社媒图
- 标注不确定信息，必要时先向用户确认

```
✓ 前端场景分析:
- 页面类型: [类型]
- 设计资产: [页面/品牌/Banner/图标/社媒图]
- 目标用户: [角色]
- 核心任务: [任务]
- 主要设备: [桌面/移动/自适应]
```

### 第二步：设计思维与 UX 策略

- 使用双钻模型：发现问题 → 定义问题 → 构思方案 → 交付方案
- 必要时输出用户画像、用户旅程、痛点、HMW 问题陈述
- 营销页可使用 AIDA：注意 → 兴趣 → 欲望 → 行动
- 数据页必须选择合适图表：柱状/折线/漏斗/热力/雷达/树图等，并说明理由
- 明确首屏价值主张、主 CTA、用户三次点击内的目标路径

### 第二步点五：快速原型与草图

在进入完整信息架构前，对关键页面输出低保真原型，快速对齐视觉预期，减少后期返工。

**适用条件**（满足任一即启用）：

- 首次设计该页面/组件，无现存参考
- 用户需求描述少于 30 字且无设计参考图
- 涉及多步骤交互流程

**输出内容**：

1. **线框图**：用 ASCII 或 Markdown 表格绘制关键页面的区块布局，标注每个区块的内容和优先级
2. **交互流**：用箭头文本描述关键路径的页面跳转和状态变化
3. **关键决策点**：标注哪些设计选择需要用户确认（如导航方式、列表 vs 卡片、弹窗 vs 新页面）

**输出格式**：

```
┌─────────────────────────────┐
│  Header (Logo + 导航)       │  ← P0
├─────────────────────────────┤
│  Hero / 核心操作区          │  ← P0
├─────────────────────────────┤
│  内容区 (列表/卡片/表单)    │  ← P1
├─────────────────────────────┤
│  Footer                     │  ← P2
└─────────────────────────────┘

交互流: 列表页 → 点击[新建] → 表单页 → 提交 → 列表页(刷新+提示)
待确认: 列表用表格还是卡片？筛选放顶部还是侧栏？
```

此步骤产出未经视觉润色，仅用于结构对齐。用户确认骨架后进入第三步细化。

### 第三步：信息架构与内容层级

- 梳理页面区块：Header / Hero / 内容区 / CTA / Footer 等
- 明确信息优先级：首屏必须传达什么，次级内容如何展开
- 定义导航、面包屑、筛选、分页、标签等结构
- 对 CMS 页面，明确模板变量和字段来源
- 对 Banner/社媒图，明确主标题、副标题、CTA、Logo、背景、视觉焦点和安全区

### 第四步：视觉风格、品牌与设计系统

定义可落地的设计系统，而不是只描述“好看”：

| 维度 | 产出 |
| --------- | -------------------------------------------------- |
| 设计风格 | 风格名称、适用场景、不适用场景、关键视觉特征 |
| 色彩 | 主色、辅助色、背景色、状态色、文本色、暗色模式覆盖 |
| 字体 | 字体配对、字号层级、行高、字重、标题/正文/注释 |
| 间距 | 4/8px 栅格或项目现有 spacing token，组件/分区间距 |
| 圆角/阴影 | 卡片、按钮、浮层、输入框规范 |
| 图标/图片 | 图标风格、图片比例、alt、占位、压缩和导出策略 |
| 组件 | Button/Input/Card/Table/Dialog/Toast 等 |
| 品牌 | Logo 安全距离、最小尺寸、禁用规则、品牌语气 |

设计系统必须采用三级 token 思路：

```css
/* 原始 Token */
--color-blue-600: #2563eb;
--space-4: 1rem;

/* 语义 Token */
--color-primary: var(--color-blue-600);
--spacing-section: var(--space-12);

/* 组件 Token */
--button-bg: var(--color-primary);
--card-padding: var(--space-6);
```

#### CSS/SCSS 工程约束

| 规则 | 要求 |
| :--------- | :-------------------------------------------------------------------------------------------------------------------- |
| 嵌套深度 | ≤3 层，禁止过度嵌套导致特异性膨胀 |
| z-index | 统一管理，定义层级常量：`--z-dropdown:100` / `--z-sticky:200` / `--z-overlay:300` / `--z-modal:400` / `--z-toast:500` |
| 单位优先级 | `rem` > `vh/vw/%` > `px`；字体/间距走 rem，布局走百分比或 vw |
| 公共样式 | 变量/mixin/函数抽离到 `variables.scss`/`mixins.scss`，组件内禁止重复定义 |
| 行内样式 | 禁止；特殊情况需注释说明理由 |
| 硬编码颜色 | 禁止；必须走 CSS 变量或设计 token |

#### 反 AI 模板式设计

**1. 结构多样性 > 视觉多样性（最核心优势）**

两个不同需求的页面，绝不应共享同一套 `Hero → 3 个特性 → CTA → Footer` 的节奏。视觉换色只是"同一模板的换肤"，结构不同才算不同站点。

- 进入第四步前，先从下列**页面宏观结构（macrostructure）清单**选一种命名结构，再填视觉细节（命名结构自带标题位置、正文构成、分隔语言、按钮语气、图片处理、揭示动效）：
  - 文档型：Long Document（长文/阅读）、Manifesto（宣言/海报）、Catalogue（目录/编号）
  - 网格型：Bento Grid（便当格）、Workbench（工作台）、Marquee Hero（跑马灯 Hero）
  - 数据型：Stat-Led（数据主导）、Quote-Led（引用主导）
  - 海报型：Letter（信笺/左栏）、Specimen（标本/衬线大标题，编辑类专属）、Display-Heavy（重显示）
  - 叙事型：Story Scroll（滚动叙事）、Split Narrative（左右分屏）
- **多样性纪律（diversification，强制）**：同一项目连续产出的页面，宏观结构必须不同；若需求模糊且未给定风格，不要默认 Specimen / 标准 SaaS 三栏，至少提供 **3 种分属不同类别**的候选（网格型 / 文档型 / 海报型各一）让用户选。
- **默认避开最易被识别的 AI 指纹**：导航默认远离 `N1a`（仅 Logo + 几个内联链接 + 右侧按钮）；页脚默认远离 `Ft3`（四列链接 + 社交行 + 小版权）。真实产品导航优先 `N1b / N5 / N11 / N13`；仅在页面确实只有 2 个去向时才用 N1a，仅当确为文档根/聚合页时才用 Ft3。

**2. 输出前自审（pre-emit self-critique，强制）**

交付任何前端产物前，在六个维度各打 1–5 分，任一 **< 3 触发一轮修订**：

| 维度 | 含义 | < 3 的典型信号 |
| ------------ | ------------------------------------------ | ----------------------------------------------- |
| Philosophy | 设计立场是否明确 | 说不清"这页想成为什么" |
| Hierarchy | 视觉层级是否一眼可读 | 标题与正文同权、重点被淹没 |
| Execution | 执行完成度 | 占位未填、状态缺失、断点没处理 |
| Specificity | 是否具体到站点而非泛化模板 | 换成任何品牌都成立、无可识别特征 |
| Restraint | 克制程度 | 动效/色彩/装饰堆满、信息过载 |
| Variety | 与上一页/同项目其他页是否不同 | 节奏、结构、主题雷同 |

自审分在交付物顶部以注释形式盖章，例如：`/* dev-expert · anti-slop: P5 H4 E5 S4 R5 V5 */`，并在第九步验证清单中记录。

**3. 诚实文案（honest copy，强制）**

用户没给的指标/数据/评价/案例数，**不得编造**。

- 数据型布局（对比行、信任条、统计块）必须使用真实数字、占位符（灰色块 + 标注"待确认指标"），或换一种宏观结构。
- `"+47% 转化"`、`"50000+ 团队信赖"`、`"10× 更快"` 一旦是编的就成套路（slop）；客户证言、Logo 墙、案例数同理。
- 用户提供的 `*.md` 简介/文档/提案视为参考素材，未经明确许可不得逐字照搬进页面。

**4. 锁定 token（locked tokens，强制）**

第四步已要求三级 token；本纪律进一步规定：

- 选定主题/设计系统后，产物内**每一个颜色、每一个 `font-family` 都必须引用命名 token**（`var(--color-accent)`、`font-family: var(--font-display)`）。禁止内联 `oklch()` / `hex` / `rgb()` 或绕过 token 块写 `font-family: "Some Font"`。
- 若需要的值尚不存在为 token，先把它**提升进 token 块**成为命名变量，再引用它；不允许"渲染中途即兴"写死值。
- **优先 OKLCH**：所有颜色用 `oklch()` 声明为 `:root` 下的 CSS 自定义属性，便于感知均匀、暗色模式覆盖与对比度控制（与第四步色彩表一致）。
- 全局样式表（如 `app/globals.css`、`src/index.css`）为**追加式**：保留其 `@tailwind` / `@import` 指令，新 token 与基础规则置于其下；用户未明确要求不得整体覆盖。

**5. 排版纯洁性（typography purity）**

- 标题与展示字形一律 `font-style: normal`（罗马正体）。标题内用 `<em>` 做斜体强调是最可靠的 AI tell；强调改用字重、强调色或手绘下划线表达。
- 斜体仅允许出现在**正文段落内**的运行强调。
- 标题/正文必须用**配对字体**（display face + body face），不允许整页单字体（除非该页刻意做纯终端风等单字体设计）。

**6. 禁止重绘假 UI chrome（re-drawn chrome）**

- 不得手绘假浏览器栏（地址胶囊 + 红黄绿圆点）、假手机框、假代码窗口（模拟标题栏 + 圆点包 `<pre>`）、假 IDE 边框——用户环境已有真实 chrome。
- 需要展示产品截图时，用真实截图包在 `<figure>`（至多一道发丝边框），或干脆去掉边框让内容独立呈现。

**7. 动效克制（motion discipline）**

- 只动 `transform` 与 `opacity`，**绝不**动布局属性（width/height/top/margin 等）。
- 只用命名缓动（`--ease-out` / `--ease-in` / `--ease-in-out`），不用浏览器默认 `ease`，UI 状态上禁止 bounce/overshoot。
- 支持 `prefers-reduced-motion: reduce`：空间动效降级为 ≤150ms 的 opacity 交叉淡入；`:focus-visible` 环必须**即时**显示，不得做出现动画。
- 默认**先砍动效再加动效**：移除某动画若不影响信息传递，就移除。

**8. 反 AI 套路门禁清单（高频 tell，交付前逐条核对）**

| # | 门禁（fail = 出现该问题） | 对应现象 |
| -- | ----------------------------------------------------- | -------------------------------- |
| 1 | 横向滚动存在 / `html,body` 用 `overflow:hidden` | 移动端被截断（应 `overflow-x:clip`） |
| 2 | 可点击文本出现两行（按钮/导航/页脚/CTA） | 触达困难、像模板 |
| 3 | 图片网格轨道用裸 `1fr`（非 `minmax(0,1fr)`） | 溢出撑破布局 |
| 4 | 标题用斜体（含 `<em>` 斜体强调） | AI tell |
| 5 | 重绘假浏览器/手机/代码窗口 chrome | AI tell |
| 6 | 内联 oklch/hex/rgb 或绕过 token 的 font-family | 破坏设计系统一致 |
| 7 | 编造指标/证言/Logo/案例数 | 不诚实文案 |
| 8 | 悬挂式标题（左栏标签 + 右栏标题两栏） | 最可靠的模板化编辑 tell |
| 9 | 连续页面结构/主题雷同（Hero→3特性→CTA→Footer） | 缺乏结构多样性 |
| 10 | 默认 N1a 导航 + Ft3 页脚 | 最易识别的 AI 指纹 |

> 完整 58 项见 Hallmark `slop-test.md`；上表是落地优先级最高的 10 项。第九步验证清单须包含本表逐条结论。

### 第五步：组件、交互状态与资产规格

每个可交互元素必须覆盖状态（**8 状态全量**，与第四步反 AI 套路纪律一致）：

- 默认 / Hover / `:focus-visible` / Active / Disabled
- Loading / Empty / Error / Success

> `:focus-visible` 必须有 ≥3:1 对比度的可见聚焦环且即时显示；Error/Success/Loading 不得缺省。组件交付建议附带 8 状态演示（各状态一行、带标签），便于一次看全。
- 表单校验错误、异步提交、防重复提交
- 弹窗、抽屉、提示、确认二次操作
- 后台管理必须考虑批量操作、筛选重置、分页保留
- 长任务必须设计 AJAX 渐进式防卡死交互：Init 创建任务、Step 分批执行、Poll 轮询状态
- Banner 必须定义尺寸、主视觉、主标题、副标题、CTA、Logo 和安全区
- 图标必须定义尺寸、线宽、圆角、填充/描边、SVG title/aria 策略
- 社媒图必须定义平台尺寸、文字安全区、导出格式和品牌一致性

#### Init-Step-Poll 前端交互规范

| 阶段 | 前端动作 | UI 状态 |
| --------- | -------------------------------------- | ------------------------------ |
| Init | 提交参数，禁用按钮，创建任务 | `queued`，显示初始化中 |
| Step | 循环请求或由 Poll 驱动分批执行 | `running`，显示进度条/当前批次 |
| Poll | 轮询任务状态，不重复提交表单 | 显示百分比、失败数、日志摘要 |
| Done | 停止轮询，展示结果和下一步操作 | `success`，允许下载/查看/刷新 |
| Failed | 停止轮询，展示错误和重试入口 | `error`，允许重试/复制错误 |
| Cancelled | 停止轮询，展示已取消状态和重新发起入口 | `cancelled`，允许重新发起/返回 |

**交互约束**：

- 轮询间隔建议 800-2000ms，页面隐藏时降频或暂停
- 连续失败 3 次必须停止轮询并提示网络/服务异常
- 用户离开页面前，如任务仍在运行，应提示任务可在后台继续或确认取消
- 禁止用户重复点击造成重复任务；按钮必须有 disabled/loading 状态
- 进度必须可感知：百分比、已处理/总数、当前步骤、失败数至少提供两项
- 取消后状态变为 `cancelled`，必须停止轮询并禁止继续提交 Step / Poll；允许重新发起或返回

### 第六步：响应式与兼容性设计

| 断点 | 设计重点 |
| ------------ | ------------------------------------------------- |
| `sm` 640px | 移动端单列布局、触控热区不小于 44px、底部操作优先 |
| `md` 768px | 平板双列/折叠侧栏、表格横向滚动 |
| `lg` 1024px | 桌面信息密度、快捷操作、固定筛选/侧栏 |
| `xl` 1280px | 大屏内容宽度控制，避免行长过宽 |
| `2xl` 1536px | 宽屏留白、网格扩展、数据看板布局 |

兼容性要求：

- 避免依赖实验性 CSS，除非明确允许
- 表格、长文本、图片必须定义溢出策略
- CMS 模板需兼容目标站点现有 CSS 作用域，避免全局污染

**移动端非妥协项（吸收 Hallmark，对应第四步「反 AI 套路门禁清单」#1/#2/#3）：**

- 断点 320 / 375 / 414 / 768 / 1024 / 1440px **全部验证**，不得仅看桌面。
- 无横向滚动：`html, body { overflow-x: clip }`（非 `hidden`，避免键盘/滚动被截断）；根容器 `box-sizing: border-box`。
- 移动端可点击文本（按钮 / 导航 / 页脚链接 / CTA）不得出现两行；必要时放宽触控高度或改为非按钮态换行。
- 网格轨道用 `minmax(0, 1fr)`（非裸 `1fr`），配合 `min-width: 0` 防 flex/grid 溢出；`img { max-width: 100% }`。
- 大屏只增不减：桌面新增细节不得反向删掉移动端必要信息。
- 不依赖 hover（移动无 hover）；触达替代用 `:focus-visible` / 可见状态。

### 第七步：可访问性、安全性与可用性检查

#### 可访问性

- 颜色对比度至少达到 WCAG AA
- 表单控件必须有 label 或 aria-label
- 键盘可访问：Tab 顺序、Focus 样式、Esc 关闭浮层
- 图片必须有 alt；装饰图可用空 alt
- 动画必须可降级，避免强闪烁和过度动效
- 交互反馈需在 100ms 内可感知，长任务必须有 Loading 或进度提示
- 空状态不得为空，必须提供说明、引导或 CTA

#### 设计评审（复杂页面 / 关键流程必做）

- 复杂页面 / 关键流程 / 上线前视觉走查，须按 `design-critique` 输出设计评审报告：10 透镜走查 + 尼尔森启发式评分卡 + 认知负荷审计 + UX 文案检查
- 评审结论分级：存在未决 P0 / P1 问题不得宣称"设计通过"；问题清单须三要素齐全（位置 / 现象 / 建议）

#### 前端安全

| 威胁 | 防护措施 |
| :--------- | :-------------------------------------------------------------------------------------------------- |
| XSS | 用户输入输出必须 `htmlspecialchars()` / `v-text` / `dangerouslySetInnerHTML` 审查；富文本白名单过滤 |
| CSRF | 状态变更请求必须带 Token；Cookie `SameSite=Strict` |
| 敏感信息 | 禁止明文存储密钥/Token 于前端代码或 localStorage；敏感数据仅存 HttpOnly Cookie |
| 接口权限 | 前端路由守卫 + 后端接口鉴权，禁止仅靠前端隐藏按钮 |
| 第三方脚本 | CDN 资源必须 `integrity` + `crossorigin`，禁用不可信第三方 JS |

| 语言 | 规则 |
| :------------- | :------------------------------------------------------------------------------- |
| **通用** | const/let 禁止 var；禁止魔法数字→抽常量；嵌套 ≤3 层；早返回消除 else |

| **React** | 函数式+Hooks；禁止循环/条件中使用 Hooks；状态扁平化；事件 handle 开头 |

#### 性能实现规范

| 类别 | 规则 |
| :-------- | :------------------------------------------------------------------------------ |
| 图片 | 压缩 + WebP 格式；`loading="lazy"` 懒加载；响应式 `srcset` |
| 组件/路由 | 路由懒加载 `() => import()`；非首屏组件异步加载 |
| 高频事件 | scroll/resize/input 必须防抖（300ms）或节流（100ms） |

| 首屏 | 关键 CSS 内联，非关键资源 `async/defer`；控制首屏请求数 |

前端交付必须有验证证据：

| 验证项 | 方法 |
| -------- | ---------------------------------------------------- |
| 视觉还原 | 浏览器截图或人工对照 |

| 交互状态 | 点击、输入、提交、错误、空状态 |

| 性能 | 首屏资源不过大，图片尺寸合理 |
| A11y | 对比度、键盘导航、aria/label |
| 设计资产 | 尺寸、导出格式、安全区、品牌一致性 |
| 安全 | XSS 过滤、CSRF Token、敏感信息不入前端代码、接口权限 |

## 国际化（i18n）规范

> 当项目需要支持多语言、多区域或跨时区时启用本节。

**启用条件**：项目要求 ≥2 种语言 / 同界面需按地区展示不同格式 / API 提示需按客户端语言切换 / 后台需多语言内容管理。

**核心规则**：

- 所有用户可见文本外置到语言包，不硬编码在组件内
- 语言包键使用 `模块.场景.键` 命名，每个键附注释说明出现位置
- 占位符用插值变量，复数用 ICU MessageFormat，不写三目表达式
- 项目指定 fallback 语言，缺失键时回落到默认语言而非显示键名
- 日期/数字/货币/百分比使用 `Intl.*Format`，时区统一存 UTC 展示时转换
- 语言包结构：`locales/{locale}.json` + `index.js` 加载器按 locale 异步加载

**API 多语言约定**：客户端通过 `Accept-Language` 头或 URL 前缀传递语言；服务端按请求语言返回错误消息和枚举文案；业务枚举值保持语言无关，文案由前端按 locale 映射；API 返回 ISO 8601 时间戳和原始数字，格式化由前端处理。

**验证要点**：所有可见文本已外置 / 复数占位符使用 ICU 规则 / 缺失键有 fallback / 至少完成 2 种语言完整覆盖校验。

## 质量标准

- 不得只给抽象审美描述，必须给出可执行的布局、组件、状态和 token
- 必须说明设计风格、色彩、字体、间距、品牌和组件规则
- 品牌/Banner/图标/社媒图请求必须输出尺寸、导出格式、安全区和验收标准
- 关键交互必须覆盖 Loading/Empty/Error/Disabled 状态
- 长任务必须采用 Init → Step → Poll，前端必须提供进度、错误、重试/取消和防重复提交
- 移动端触控热区不得小于 44px
- 表单必须包含校验规则和错误提示
- 输出到页面的用户内容必须转义，CMS 模板必须避免 XSS
- 图片必须有尺寸、比例、alt 和降级策略
- 必须说明响应式断点和溢出处理
- 前端产物必须过「反 AI 套路门禁清单」10 项 + 输出前自审盖章（六维均 ≥3），且宏观结构与同项目其他页不同
- 前端交付必须包含浏览器验证方法或证据
- CSS 嵌套深度 ≤3，z-index 必须统一管理，颜色禁止硬编码
- 前端安全必须逐项检查：XSS 过滤、CSRF Token、敏感信息不入 localStorage、接口权限后端兜底
- 复杂页面 / 关键流程必须附设计评审结论（10 透镜 + 评分卡 + 认知负荷审计，无未决 P0/P1，见 `design-critique`）
- 命名遵循规范：组件大驼峰、工具短横线、布尔 is/has 前缀、函数动词开头
- TypeScript 禁用 any，函数签名必须完整标注类型
- ESLint/Prettier 基线必须输出 2空格/单引号/分号/末尾空行四项

## 失败回退机制

| 步骤 | 失败条件 | 回退目标 | 最大重试 | 不可恢复时升级路径 |
| ------------------------------------ | -------------------------------------------- | ------------------------------------------ | -------- | -------------------------------------- |
| 第一步：需求与场景分析 | 页面目标或用户角色不清 | 列出2-3种页面/资产类型假设，由用户选择 | 2 | 输出澄清问题清单，等待用户确认 |
| 第二步：设计思维与 UX 策略 | 用户路径或转化目标不清 | 使用最小用户旅程和 AIDA 草案 | 1 | 输出 UX 假设清单 |
| 第三步：信息架构与内容层级 | 内容素材不足 | 生成结构骨架并标注待补文案/图片 | 1 | 输出素材缺口清单 |
| 第四步：视觉风格、品牌与设计系统 | 无品牌规范 | 使用中性设计系统，标注可替换 token | 1 | 要求用户提供品牌色/参考站 |
| 第五步：组件、交互状态与资产规格 | 业务流程或资产规格不完整 | 覆盖通用状态和标准尺寸，复杂状态标注待确认 | 1 | 输出状态机/资产规格草案 |
| 第六步：响应式与兼容性设计 | 目标设备不明确 | 默认移动优先 + 桌面增强 | 1 | 标注兼容范围假设 |
| 第七步：可访问性、安全性与可用性检查 | 无法测量对比度、安全基线缺失或键盘行为不可用 | 输出检查清单和手动验证步骤 | 1 | 标注未实测项 |
| 第八步：前端实现方案 | 技术栈未知 | 输出 HTML/CSS 通用方案，避免框架特定代码 | 0 | 要求用户确认技术栈 |
| 第九步：浏览器验证 | 无运行环境 | 输出本地验证步骤，标注未截图 | 1 | 等待用户提供运行地址或截图 |
| 第十步：记录到项目记忆 | 项目记忆系统不可用 | 输出前端设计决策到本地文件 | 1 | 标注"设计规范未沉淀"，提示用户手动保存 |
