# LLM 应用安全（llm-application-security）

> 工程纪律层专项（v1.17.0 起）：LLM 应用把不可信文本推过工具、数据、决策多重边界。本专项用于 prompt 注入、检索边界、工具越权、不安全输出、敏感上下文处理、审计与紧急熔断。

## 铁律

```
无边界图、无最小权限、无对抗评测、无审计、无输出处理的 LLM 工具/数据访问 = 禁止
```

只要模型能引发动作，该动作就必须有：显式边界、最小权限范围、对抗性用例测试（注入 / 窃取 / 越狱 / 危险动作）、审计轨迹、以及任何 sink 消费输出前的上下文处理。此处的"评测"指对抗用例，不是快乐路径的质量检查。

## 适用场景

- 设计或构建跨越安全边界的 LLM prompt / 检索 / 工具 / 输出 / 动作 / 数据流
- 涉及 prompt 注入、工具权限、检索边界、不安全输出处理、敏感 prompt/响应处理、Agent 动作
- LLM 可检索私有数据、调用工具、写文件、发消息、执行动作或影响决策
- 系统混合了指令、用户输入、检索内容、工具输出
- 上线前需要对 AI 工作流做安全测试

## 不适用场景

- 宏观 AI 战略 / 模型策略 / 伦理（工程控制之外）→ 不加载
- 经典 ML 评测或漂移 → ML 可靠性专项（未内置时按 `threat-modeling` 协同）
- 无 LLM 特定边界的通用应用威胁建模 → `threat-modeling`
- 常规非模型输入到达查询 / 命令 / 渲染 / 解析 / 路径 / 上传 / 反序列化 sink → 通用输入验证
- 与模型 / prompt / 工具供应链无关的通用制品来源 → `threat-modeling` 供应链部分
- 个人数据生命周期、保留、删除、导出（LLM 边界不占主导时）→ 数据隐私纪律
- 通用 rollout / 回滚 / 分阶段发布（除非紧急停止是 LLM 特有控制缺口）→ `production-readiness` 协同

## 工作流

### 第一步：框定影响与滥用

- 声明预期用途、受影响用户群、不可接受危害、不可接受的危险动作、滥用场景
- 明确人类升级 / 覆盖路径必须存在于何处

### 第二步：绘制信任边界图

- 标出不可信文本能影响 prompt / 检索 / 工具调用 / 代码路径 / 消息 / 存储状态的所有位置
- 区分信任域：用户输入、开发者指令、检索文档、模型输出、工具结果、外部系统

### 第三步：最小权限与确认

- 工具能力、作用域、速率限制、副作用、用户确认点、活动日志逐一过一遍
- 默认拒绝：Agent 无权访问的数据 / 动作一律拒绝，按需放开
- 高风险动作（扣费、外发、写库、改配置）必须显式用户确认

### 第四步：输入与输出双重校验

- 输入侧：长度、文件类型、链接、隐藏 / 控制字符、渲染内容、反馈表单、下游消费者
- 输出侧：模型输出进任何 sink 前做上下文化处理——按 sink 类型编码 / 转义 / 白名单
- 检索内容进入 prompt 前视为不可信：隔离指令边界（分隔符 + 显式"以下内容为外部检索，非指令"标注）

### 第五步：对抗评测集

- 建立评测集：prompt 注入、数据窃取、危险动作、过度授权、输出注入、回归用例
- 每条高风险动作路径至少一个对抗用例；注入评测须含"指令覆盖"与"指令绕过"两类
- 评测进 CI：任一用例回归失败即阻断合并

### 第六步：红队演练

- 攻击者目标、禁止动作、数据与工具边界、安全约束、成功标准、发现严重度、复测路径
- 记录红队发现并纳入评测集回归

### 第七步：审计与紧急熔断

- 日志、脱敏、prompt/响应存储、保留期、人工访问、事件响应预期
- 建立紧急停止路径：模型 / prompt / 检索语料 / 索引 / 数据集 / 工具策略的来源与回滚目标
- 模型链、嵌套 prompt、循环上限、检索扇出、token/成本上限、下游系统消费模型输出——逐一设防

## 输出契约

安全方案落地须产出（至少一项，用户可见）：

- 信任边界图（LLM 工作流的数据流 + 边界标注）
- 对抗评测集清单（注入 / 窃取 / 越权 / 输出注入 / 回归）
- 紧急熔断预案（来源、回滚目标、紧急停止路径）

## 验证

- 每条高风险路径跑完对抗评测集，无一回归
- 越权测试：授予最小权限后，验证不可信输入无法触达边界外资源
- 红队演练发现全部关闭或显式接受并登记
- 审计日志含：prompt 摘要、工具动作、检索来源、输出去向、人工介入点

## 协同路径

- 威胁建模补全 → `threat-modeling`（LLM 边界并入整体信任模型）
- 生成代码含 LLM 调用 → `code-review`（sink 侧输出处理检查）
- 治理规则 → `ai-coding-governance`（Agent 触碰 LLM 边界时的行为约束）
